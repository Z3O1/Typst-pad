# 写作模式渲染模型

## 决策

写作模式要呈现 Typst 真正的排版，又要让用户直接编辑源文档。产品采用混合视图：纯 markup 段落和标题保留为 CodeMirror 真实文本；需 Typst 排版的复杂块使用引擎生成的局部 SVG，光标进入后显示源码。源码是唯一数据模型，SVG 是可丢弃的呈现缓存。

直接用 CSS 仿造 Typst 会在字体、断行、宏、包、页面设置、字距和上下文布局上持续偏离引擎；整篇 HTML 导出也不能给出编辑器里的局部可编辑语义。局部切片复用真实编译结果，同时把复杂源码的编辑交还给 CodeMirror。纯正文保留文字 DOM，减少不必要的切片并维持原生选择和输入。

切片不铺每字形文字层。那会要求将 Typst 输出的字形和布局重新映射回可编辑源码，增加复杂度和错位风险；当前明确接受切片内查找、拼写检查、复制投影和无障碍访问受限。链接以排版几何热区实现，不能把 SVG 当作可编辑 DOM。

## 工程约束与取舍

整份源文档仍需在 Typst 上下文中编译，局部切片按可见窗口输出。切片带有文档/上下文/版心来源戳，才能安全复用或拒绝过期结果；命中测试也必须绑定当前会话与几何。滚动窗口或版心变化可触发重排，但不应让输入去抖不断延期。Rust 侧需统一输出块几何，前端拥有“直接正文还是复杂切片”的呈现意图，避免两套独立语法判据漂移。

Typst 的墨迹可超出布局帧，裁切要以字形和图形的 ink bounds 为准，并限制在对应源块的 y 带内。跨页脚注/浮动内容不能靠扩大当前块裁剪范围解决，否则会侵入后续块；需要单独呈现模型或多片段协议。超大块当前优先源码编辑，不能因性能压力取消单块上限或反复渲染同一块。

## 当前事实与限制

- 纯 markup 段落、标题按当前 lexer/块类别规则保留真实文本；含 code、raw 或注释的块采用切片。某些 Typst markup 简写、引用、标签等暂未获得独立可视映射，仍可能按源码显示。
- 源块表不保证连续覆盖全文；前端按行生成的 covers 才负责源码和切片格子连续。无输出块只有在成功编译确认后才隐藏。
- 表格按整块呈现；超大单块跳过 SVG。脚注正文及部分浮动内容目前可能不在源块裁剪带内。展开源码的自然高度可能与排版高度不同，有限占位只能避免部分收缩，不能消除内容本身增高。
- 浏览器开发桩和静态夹具不覆盖桌面文件 IO、真实包解析及所有 WebView/IME 行为；任何性能数字和验收结论需注明测量环境。

## 尚未实施的设计建议

以下来自 2026-09-22 的评估记录，之后代码仍有演进；仅保留为方向，不代表当前代码现状、已承诺或已实现。实施前应复核代码、夹具和产品需求。

1. **纯正文免生成 SVG（性能优化）**：当前后端对窗口内块生成切片，而前端会将可编辑正文标记为 revealed，形成不显示的渲染成本。可由前端把呈现意图传给后端；判据应单一来源，不要在 Rust 重写一套 lexer。协议要区分“有意免渲”与“缺图”，否则会造成补渲循环。
2. **简单列表直接编辑**：先对无嵌套、无 code/raw/comment 的简单列表做原型。列表真实排版与文本行间距不同，应先以真实文档测量，再决定呈现策略；不宜删除复杂块回退。
3. **行内 code/raw/link 白名单**：目前整块判据明确而保守。只放开完整闭合且可逆的构造会增加例外规则；这是产品决策，尚未决定。候选规则必须定义源码与显示的往返行为，并同步实现规范。
4. **受限表格编辑**：只考虑已明确列出的静态 `#table` 子集，采用精确源区间编辑；宏、动态 cells、合并单元格或未知参数应退回源码，不能整表重序列化。
5. **图片与资源操作**：已有链接格式命令不等于图片资源管理。图片插入/尺寸编辑尚无完整交互设计；引用路径、资源复制和写盘安全需要单独定义，继续使用既有路径校验与统一写入链。
6. **脚注及跨页内容**：近期可考虑显式提示“此内容在源码/源码模式中查看”；独立脚注呈现或多片段协议需要另行设计。`pages > 1` 不能伪装成完整单片段切片。
