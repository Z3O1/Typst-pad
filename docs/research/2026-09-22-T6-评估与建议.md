# 报告 T6 各子项的评估与建议（不做产品改动）

日期：2026-09-22。基线：`fix/writing-stability-t0-t1` 分支（T0–T5 已实施，八套浏览器验收全绿）。

报告 §7 的 T6 是**分别评估**的一栏，其中「行内 raw/link 白名单」明确写着"**会改变当前
'含 code/raw/comment 即复杂'的明确规则，属于备选方案，不纳入默认 T0–T5 实施**；先形成产品
决策并同步规则/03 册，再做"。所以本文**只给评估与建议**，没有改任何产品代码、也没有改规则文档。

下面每项按「现状（代码证据）→ 可行做法 → 成本/风险 → 建议」写。成本单位是"熟悉本项目的一名
开发者、含本地验收"，与报告 §11 同一口径，不是工期承诺。

## 1. 纯正文免生成 SVG（P2，报告问题清单 P2）

**现状**：`src-tauri/src/block_geometry/crops.rs` 对**窗口内**的每一块都渲一张 SVG（`:316` 一带），
而前端的 `isDirectlyEditableTextBlock`（`live-preview/block-decorations.ts`）对"纯 markup 的
Paragraph / Heading"标了 `revealed = true` —— 也就是**后端渲了、前端不显示**。窗口化已经把成本
限在视口 ±4000 字符，所以这不是漏内容，是白付一份渲染。

**可行做法**：前后端约定一个 **render intent**：请求里带上"这一块我打算怎么呈现"（或者由后端按
同一套判据自己判断），对可靠判定为纯正文的块**只回几何、不回 SVG**；不确定的一律按现在这样渲。

**成本/风险**：0.5–1 人日。风险全在"判据必须同源"：后端此前**没有** `isDirectlyEditableTextBlock`
那套判据（它在前端的 lexer 里）。若后端自己写一份，就会多出第二份复制品（`writing-blocks-visual`
里已经有一份正则复制品的前车之鉴）。**建议：intent 由前端给**（前端本来就算了 opaque 区域），
后端只按 intent 决定渲不渲；同时"缺图"的判据要跟着改（现在 `svg === ""` 会被当成"该补渲"——
免渲的块必须是 `skipped` 那种"有意不渲"，否则会 150ms 循环重编译）。
**建议**：做，但排在任何"表格/列表可编辑"之前不值当；它是纯性能项，收益与视口内正文块数成正比。

## 2. 更少列表切换（简单列表可编辑文字）

**现状**：`Block.kind === "ListItem"` 的块一律走切片（`isDirectlyEditableTextBlock` 只放行
Paragraph / Heading），所以写作模式里列表整块是图片、点进去才展开。

**可行做法**：给**简单列表**（无嵌套、无代码/raw/注释、单层）一条"真实文本"的原型，嵌套/含代码
仍回切片。这不是"删掉 kind 判据"，而是**加一条更窄的判据**（kind + 行形态 + 无复杂区域）。

**成本/风险**：2–4 人日（要真夹具证明保真 + 键盘语义不回归：续项、缩进、竖直移动、拖选）。
风险：列表的"标记隐藏"（`- ` → `• `）与 typst 的列表间距是引擎画的，退回文字后**间距必然不同**
（W2 的同一类问题），用户可能觉得"列表变挤了"。
**建议**：先做 #1 与 #3 的产品决策，这一项**最后**做；做之前先用真夹具量一次"文字列表 vs 切片"
的纵向偏差，拿数据决定间距。

## 3. 行内 raw/link 白名单（**需要产品决策，先不动**）

**现状**：`isDirectlyEditableTextBlock` 的判据是"块内有没有 code / raw / 注释区域"
（markup 里的直引号不算）。行内 `` `code` `` 与 `#link(...)` 都会让**整段**退回切片。

**可行做法**：只对"**完整闭合且可逆**"的已支持构造放开（例如行内 `` `x` ``、`#link("…")[文字]`），
其它一律保持复杂。必须同时给出"渲染形态与源码形态的往返"判据。

**成本/风险**：2–3 人日 + 一次产品决策；风险是**规则被削弱**：现在"含 code/raw/comment 即复杂"
是一条**明确可测**的规则，白名单会把它变成"大部分行内构造可编辑 + 例外清单"，判据复杂度上去了，
而收益只是"少一次点击"。
**建议**：**先要产品决策**（用户要不要这个体验），并且**必须先同步 03 册与 AGENTS 的规则句**，
再动代码。当前状态下我不动它。

## 4. 表格（仅静态 `#table(columns:..., [cell],…)` 的受限编辑）

**现状**：`#table(...)` 所在的 Paragraph 含 `#` → 走切片。

**可行做法**：只识别**静态**表格（字面 `columns:` + 一串 `[cell]`），在源码上做**精确区间替换**
（插一行/删一行/改单元格文本），不整表重序列化（否则参数、`stroke`、`align` 全丢）。

**成本/风险**：3–6 人日（单独估期）。风险：Typst 的表格参数极多，任何"我没见过的写法"都必须
**原样退回源码**；`table.cell` / 合并 / 动态 `..cells` 一律不碰。
**建议**：值得做（写作场景里表格常见），但要**独立一期**，且先落"能识别的形态清单"再写代码。

## 5. 图片/链接（菜单插入、尺寸/链接编辑）

**现状**：没有插入图片/链接的菜单项；`#image("…")` 的路径校验在 Rust（`validate_write_path`
那一套只管**写文件**，图片是**引用**外部资源，路径解析走 `typst_world` 的项目根规则）。

**可行做法**：菜单插入（写 `#image("相对路径")`）+ 现有保存/路径安全链；尺寸/链接编辑按
"选中 `#image(...)` 时露出可改的参数"。

**成本/风险**：2–4 人日。图片资源落盘属于**独立的文件操作设计**（不能绕过 `validate_typ_path` /
`validate_write_path` 与"写盘只有一条路"两条红线）。
**建议**：可与 #4 同期评估，但**先写文件操作设计**（拷到项目目录？还是只允许相对路径引用？）。

## 6. 脚注 / 跨页复杂块

**现状**：脚注内容被 typst 排到页底，而写作模式的切片是**按块**取的裁剪带 —— 脚注不在任何块的
带里，所以写作模式**看不到脚注正文**（AGENTS「已知未决」里那条）。`crops.rs` 已有 `pages`
字段（`Block.pages`），但前端没有消费"这一块跨了几页"。

**可行做法**：① 明确呈现缺口（状态栏/按钮提示"这块有脚注，源码模式可见"）；② 研究独立的脚注
显示（把脚注块单独切出来贴在页底）；③ 多片段协议（一块跨页时给多张带，而不是只给第一页）。

**成本/风险**：①0.5 人日；②③各 3–5 人日且要动 Rust 的带协议。**报告 §7 的边界写得很清楚**：
不放宽裁剪带去覆盖后文、`pages > 1` 不得冒充完整切片。
**建议**：先做 ①（把"看不到"变成"看得见地看不到"），②③ 另立一期。

## 7. 纯文字复制（新命令，从语义/源码投影）

**现状**：默认复制走源码（无损），这在报告 §3 的表格里被定为"首期确保 Typst 源码复制无损"。
`copyPlainText`（`core/clipboard.ts`）已经在用（复制诊断信息），但**没有**"复制纯文字"命令。

**可行做法**：新命令（菜单 + 快捷键）把选区投影成纯文字：优先用源码做**语义投影**（去掉
`= ` 标记、`*`/`_` 定界符、`#link(...)[文字]` 只留文字、`$…$` 保留源码或渲染文本），
**不从 SVG 里抓文本**（切片没有文字层，见 AGENTS「已知未决」）。

**成本/风险**：1–2 人日；风险是"投影规则"本身又是一套需要产品决策的语义（公式复制成什么？）。
**建议**：可做，且**默认行为不动**（源码复制保持无损）——这与报告一致。

## 8. 专注 / 打字机模式

**现状**：没有。CM 侧已有 `scrollIntoView` 的正确用法（T1 刚做过），做这个不需要新机制。

**可行做法**：可选菜单/快捷键；"专注"= 弱化非当前块（CSS + 装饰类），"打字机"= 光标居中
（`anchorPosEffect(..., "center")`，注意本批发现 `y:"center"` 在 CM 里会忽略 yMargin，
要用 `y:"start"` + yMargin 表达）。

**成本/风险**：1–2 人日。**默认必须关闭**、尊重用户手动滚走（报告 T6 的边界）。
**建议**：可做，优先级最低 —— 它是增强，不是修问题。

## 汇总建议顺序

| 优先级 | 子项 | 理由 |
| --- | --- | --- |
| 1 | #1 纯正文免生成 SVG | 纯性能、无 UX 争议；但要先定 intent 协议与"免渲 ≠ 缺图"的判据 |
| 2 | #6① 脚注缺口的可见化 | 半天成本，把"神秘缺失"变成"明确的缺口" |
| 3 | #7 纯文字复制 | 小而独立，默认行为不动 |
| 4 | #2 简单列表可编辑 | 收益明确但要先量间距；排在 #1/#3 决策之后 |
| 5 | #4 表格受限编辑 / #5 图片链接 | 各需独立设计（表格形态清单 / 文件操作设计） |
| 6 | #3 行内 raw/link 白名单 | **必须先产品决策 + 同步规则**，本批不做 |
| 7 | #8 专注/打字机 | 增强项，最低优先级 |

## 本轮明确没做的事（免得下一手误以为漏了）

* 没有改任何产品规则（尤其 #3 会触碰"含 code/raw/comment 即复杂"这条，报告要求先决策）；
* 没有改 Rust 的带协议（#6 的 ②③ 要动它，属独立一期）；
* 没有加"复制纯文字"命令、没有加专注/打字机（#7/#8 是新增功能，不是修 T0–T5 的问题）；
* 没有升级依赖、没有改版本号 / CHANGELOG 版本段、没有发布。
