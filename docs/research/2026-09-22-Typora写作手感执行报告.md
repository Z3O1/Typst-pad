## 1. 推荐决策

保留现有 Svelte + CodeMirror 6 + Tauri + 原生 Typst 架构，继续以 Typst 源码为唯一真相。先把当前两种呈现之间的切换做好，再扩充写作功能。

第一阶段交付应包括：单行行间公式编辑前后对齐一致、公式点击复用现有光标锚定、模式切换停止直接写滚动位置、异步点击不再接受过期结果、复杂块进入和退出有明确的稳定策略。接着统一编译调度与结果版本，防止旧图、新几何和新文档混用。列表与表格编辑排在这些工作之后。

不能承诺任意 Typst 源码展开后与排版等高。一个六行 `#table(...)` 可能只生成两行表格；要求二者强行等高会导致文字裁切、嵌套滚动或巨大留白。目标应是**当前编辑位置稳定、呈现只收敛一次、没有无关段落反复跳动，源码始终可见可编辑**。

这项判断来自本仓库已经可用的真实文本/切片链路，以及结构化编辑器需要额外 schema 与转换的成本；不是声称其他架构不可能实现。参见 [CodeMirror 装饰机制](https://codemirror.net/examples/decoration/)、[Tiptap schema](https://tiptap.dev/docs/editor/core-concepts/schema)、[ProseMirror Markdown 模块](https://github.com/ProseMirror/prosemirror-markdown)。

### 2.3 现有视觉验收的具体盲区

`scripts/browser-check/writing-mode-scenes.mjs:211` 之后的“光标进出块页面不许变高”，实际只测“中文长段落”和“标题层级”。这些现在已经是持续真实文本，不能代表代码、表格和公式的切换。

其他夹具编辑后不再与原文相同，开发桩会转回假排版（该脚本后段已有注释）。因此，**任意编辑后的真实排版正确性**要用新旧两份真实夹具或桌面链路验证，不能把桩产物误当引擎结果。

| 专注/打字机 | 支持弱化非活动内容、光标居中 | 次要可选增强，不用它掩盖跳动。见 [Focus and Typewriter](https://support.typora.io/Focus-and-Typewriter-Mode/) |

没有从官方资料确认 Typora 的全部 IME、空嵌套项退格和撤销分组细节。这些只能标成待对照观察，或明确写成 Typst-pad 自己的产品决定。

## 6. 目标交互契约

| 内容 | 非编辑态 | 进入/编辑态 | 离开 |
| --- | --- | --- | --- |
| 普通正文、标题 | 真实文字，局部隐藏标记 | 光标碰哪枚标记就露哪枚 | 保留真实文字 |
| 行内公式 | 缓存匹配时 Typst SVG | 整段公式源码；允许自然折行，保持原行基线/锚点 | 同版结果就绪才一次替换 |
| 独占单行的行间公式 | 居中公式 | 居中源码行，有限最小行盒，文字可增长 | 清理临时占位并一次收敛 |
| 多行行间公式 | 现有块 widget | 展开所有源码行，不把多行源码强行居中 | 匹配结果落地，不套“整块选中不展开”例外 |
| 代码、表格、宏等复杂块 | Typst 切片 | 真实 CM 源码；活动位置锚定，长源码正常长高 | 已编辑则等新鲜切片；未编辑可复用匹配产物 |
| 超大或失败块 | 源码回退 | 正常编辑 | 不循环补渲、不空白占位 |

“同版”包含文档、上下文和布局，不只比较源码字符串。编辑中不展示遮住光标的旧图；合成中不冻结文档本身。直接点击与键盘移动共用状态规则，方向键既有逐源码行语义保持。

### T0：把“少跳动”变成可测量目标（1–2 人日）

每帧记录进入前、点击/键盘事务后、measure 后、编译结果后 500ms 内的锚点 y、活动行盒、上下段落 y、contentHeight、列宽。用 `requestAnimationFrame` 采样轨迹，而非仅等 500ms 比终态。通过开发测试钩子读取 CM 状态，逐步替代脚本里依赖内部 `cmTile.root.view` 的取法。

覆盖 T8 矩阵；对高度增加和滚动位置漂移分别出指标。不要用 CLS 代替编辑交互位移：这里要直接测几何。对 fake、真实静态夹具、真实动态编译分别标识，缺夹具硬失败。

完成标准：至少将 V1 和代码/表格高度切换纳入回归；可稳定复现两次，不改断言容忍度掩盖问题。回退：保留诊断数据，不改变产品。

### T1：对齐和锚点的最小修复（1–2 人日）

修改：`Editor.svelte`、`scroll-anchor.ts`、`live-preview/widgets.ts`、`math-decorations.ts`、`theme.ts`，及相关测试。

1. 将“独占单行 display math 的行装饰”放在 reveal 分支之前，编辑/渲染沿用同一对齐。仅限 `block !== null && !range.multiline`；同行前后有正文、多行公式不套用。
2. 三个 widget 点击共用 reveal helper：`preventDefault`，在同一事务提交 selection 与 `anchorPosEffect`，随后 focus。公式仍落源码起点，不宣称支持逐数学字形命中。
3. `restoreCaretAnchor` 使用已保存的视口偏移构建 `scrollIntoView` 目标，删除直接赋值。用 CM `requestMeasure` 分离布局读取和事务写入；不依靠无限 rAF 重试。捕获前清掉旧 anchor，窗口销毁/模式再次变化则废弃旧请求。
4. 不给所有异步刷新无条件加滚动补偿；普通刷新先依赖 CM 原生锚定，仅显式编辑切换表达一个滚动目标，避免两套锚点打架。

完成标准：V1 的 center→start 消失；100%/150%/200% 下点击、左右键、Ctrl+E 均保留正确源码位置与焦点；整选替换、跨行公式例外不回归。回退：分别撤回新增 helper/行装饰策略，保持现有可编辑源码退路。

### T2：结果与点击的一致性（2–3 人日）

修改：`core/block-state.ts`、`block-plan.ts`、`typst-engine.ts`、`+page.svelte`、`block-drag.ts`；若扩协议，同步 Rust `crops.rs`/`hit.rs` 与浏览器桩。

引入以下**逻辑模型**；名字可按现有类型调整，状态职责不得省略：

```ts
type RenderStamp = {
  sessionId: string;       // 打开/新建/重读后改变
  documentRevision: number;
  contextRevision: number; // 前缀、字体、路径、依赖刷新
  layoutRevision: number;  // CSS 版心宽度及排版设置
};
type CropBundle = {
  stamp: RenderStamp;
  geometryId: number;
  svg: string;
  metrics: CropMetrics;
  links: LinkHotspot[];
  freshness: "fresh" | "stale";
};
```

请求发出时复制快照，await 后与当前完整 stamp 比较。第一步可以在前端闭包保存 stamp，不必立即改全部 IPC；逐块缓存需要把产物归属保留下来。打开文件时清理所有待执行状态。依赖变化只对当前能观察到的刷新事件递增 contextRevision；未有文件监听时，不能声称已经覆盖自动外部文件更新。

点击同时捕获 document、geometryId 和 action token；await 后再验一次。后发点击、键盘编辑、文档切换、鼠标接管取消都使旧 token 作废。**作废应取消本次操作，不能把 null 当块首 fallback 后继续提交**；区分 `cancelled` 与“当前请求命中不可用”。字节转换用请求那份 doc，并确认仍为当前 doc。

沿用切片按完整 bundle 处理。新旧版不一致时可以保留旧图作为暂时外观，但该块标 stale、精确命中关闭、进入可见窗口必须请求新图；判据不能继续仅看 `svg === ""`，否则旧图永不刷新。保留 `skipped` 不补渲，并防止同窗口重复请求。不要简单把全表 exact 关掉而永久损失所有新鲜块定位。

补渲去重键必须包含完整 `RenderStamp + 请求窗口/目标块`，不能沿用只有 `from:to/all` 的 `lastBlocksWindow`。同一窗口的新 revision 必须允许补渲；失败需求结束在途状态，避免永久被旧键挡住，也避免立即无限重试。

完成标准：0/350/1000ms 延迟和乱序响应下零过期选择提交；改宽度/字体/前缀后无旧图配新几何；链接热区与 SVG 一起更新。回退：禁用沿用缓存，回到可见区域新鲜图/源码退路，仍保持窗口化。

### T3：统一调度与输入法安全（2–4 人日）

修改：新增 `core/writing-compile-scheduler.ts` 及针对性测试；接入页面现有 edit、blocks-needed、resize、context 入口；调整 `Editor.svelte`、`math-queue.ts`/请求模块。

策略：每窗口最多一个在途块编译和一份最新待执行需求；新需求替换 pending，不追加队列。保持原来的 150ms 写作去抖和 240ms 公式让路意图；合并理由和最新视口，不为每个入口各挂定时器。旧结果仍要版本过滤，队列合并不能替代结果校验。

输入法从 `compositionstart`/`compositionStarted` 保护，不只依赖第一次输入后才变真的 `composing`。合成期间立即同步 editorDoc、映射 ranges/covers，但不主动启动新后台块编译，不提交替换组合区域 DOM 的异步呈现；已经启动的编译可完成并暂存。结束后读取最终文档快照，合并刷新和编译。逐段确认本机 CM 版本事件顺序，不假设一个微任务一定覆盖所有 WebView2 行为。

公式结果先入缓存，统一每绘制帧发一个 refresh；文档切换后旧回调作废。选区移动只重算展开/选中色，文档扫描缓存以 doc/context revision 为键；任何 docChanged 都必须更新扫描，不允许持有错位区间。

CM 提供 `requestMeasure`、composition 状态和 decorations 接口；本机 `@codemirror/view` 6.43.7 的 `.d.ts` 已核对。依据 [官方源码](https://github.com/codemirror/view/blob/main/src/editorview.ts) 和 [装饰示例](https://codemirror.net/examples/decoration/)。在线 API 页抓取 403，因此版本细节以本机声明和源码交叉确认。

完成标准：合成期间零次新后台块编译启动，文本不丢不重复；pending 数始终 ≤1；每帧最多一次外部刷新；纯选区移动不重新词法扫描整篇。后端仍一次一编译，不添加并发 Typst 编译；不声称可以中断已经运行的 `typst::compile`。

### T4：公式与复杂块的稳定编辑会话（3–5 人日）

依赖 T0/T2。修改：新增 `editor/live-preview/edit-session.ts`，接入 StateField、math/block decorations、widgets；尽量先不改 Rust。

会话状态为 `rendered → editing → awaiting-render → rendered`，失败停留可编辑源码。保存映射后的 source range、RenderStamp、进入时渲染盒高、锚点、是否编辑、临时占位值。范围通过 `tr.changes` 映射；文档切换、块删除、宽度变化使旧度量失效。

进入过程：在 View 层测量旧盒；同事务撤替换、保留真实 CM 文本并给滚动目标。源码自然高度小于有效渲染高度时，补 `max(0, renderHeight - sourceHeight)` 的临时空白；大于渲染高度时正常增长。单行公式优先用行级最小高度；多行/复杂块可用尾部零交互 spacer。spacer 由 StateField **直接**提供块装饰，不能从 ViewPlugin 的间接 decorations 改垂直布局。其位置、空文档、最后一行必须实测，不制造空 range。

离开过程：没有改内容、stamp 仍匹配则复用产物；改过内容则保持源码到新结果就绪，再把切片替换、临时占位清理和一次滚动目标合并提交。失败保留源码与诊断，不无限保留巨大 spacer。若用户迅速进入下一块，以当前活动块/可见阅读锚点为准，不能把用户拉回刚离开的块。

**范围限制：**临时 min-height 能抑制高公式展开成短源码的收缩，不能消除本次代码 +94px、表格 +83px 的自然增长。对后者验收活动位置稳定和单次变化。拒绝固定最大高度、裁切、第二个 contenteditable、固定全篇纸高和反复动画。建议初版不加高度动画，避免拖动/输入时命中坐标不断变化。

初版占位上限明确为 `MAX_RESERVED_VIEWPORTS = 1`：所需空白超过一个编辑器可视高度时不补占位，仅锚定；否则补值不得超过进入时有效渲染高度。占位绑定唯一会话且不得累加；块删除、切文档、宽度改变、错误回退时撤销。添加等于上限、略超上限、连续进出与失败清理测试，后续调整常量必须附新的几何证据。

完成标准：进入/退出 20 次无累积空白；旧结果不使编辑区域闪回切片；源码比图长时仍完全可编辑；文档首尾和滚动余量不足单列合法边界；无连续两次相反方向的非预期位移。若占位造成命中或选区回归，撤回占位，仅保留 T1 锚定，不能拖累基础修复。

### T5：恢复连续写作交互（2–4 人日）

修改：`editor-keymap.ts` 改成模式感知配置；复用 `codemirror-lang-typst/lezer` 导出的 `insertNewTypstListItem`、`insertTypstListContinuation`；配套键盘/浏览器测试。

本机安装 0.6.0，`dist/lezer.js:2470-2537` 已实现同级拆项、空顶层退出、空嵌套项上移、续行。当前 `editorKeymap` 与依赖均为 Prec.high，本地在前且 Enter 无条件返回 true，因而遮住它。首选只在写作模式把列表命令排到普通继承缩进之前，返回 false 再走现有规则；**不重写第二份列表 Enter 状态机**。依据 [官方仓库](https://github.com/kxxt/codemirror-lang-typst) 和本机安装包双重确认。

写作列表中 Enter 续项、空项退出；Shift-Enter 复用续行；非列表、源码模式仍保留原有缩进规则。Tab/Shift-Tab 仍以四空格为层级单位，处理整个项目及续行/子项；第一阶段无法可靠识别的选区回现有普通缩进，不能猜结构。Backspace 先规定行首降级/去标记，再实现；正文字符删除沿用 CM。

同时修复两个代码可确定的命令边界：`write-commands.ts:92` 取消带缩进的同类列表时删错行首空格，应删除缩进之后的标记；`:142` 行间公式的前缀 `$\n  ` 长4而 anchorOffset写3，应由前缀长度计算。测试断言选中的文本确为原正文，不继续锁错误常量。

所有新命令一次用户动作一个事务；测 typing→format→typing→undo/redo，而不是只检查文档最终字符串。菜单与快捷键仍共用命令，不加工具条；补全框和 IME 拥有 Enter 时不抢键。

## 8. 验收矩阵与拟定通过线

以下阈值是**项目建议验收线**，不是从 Typora 测出的规范。T0 在 Windows 基线建立后可按端点条件细化，但不能为过测试任意放宽。

| 维度 | 样本与动作 | 判据 |
| --- | --- | --- |
| 几何稳定 | 行内短式、高分式、单行/多行行间式、raw、表格、带脚注段落；点击/箭头进出各20次 | 有滚动余量时预定编辑锚点 P95 偏移 ≤4 CSS px，最大≤8px；首尾夹紧单列；文本、选区正确 |
| 动态轨迹 | 逐帧记录进入/退出及结果到达 | 一次动作至多一次必要的结构收敛；无先缩后涨、额外反向滚动；不只看终态 |
| 窄窗/缩放 | 600/1000/1400px；100/150/200%；跨显示器 DPI 桌面验证 | 使用 CSS px 判据；无横向溢出/字号跃变；宽度修改只落同版结果 |
| 合成 | 拼音连续、数字选词、空格/Enter确认、Esc取消；标记/公式/列表/块边界 | 零丢字/重复/失焦；editorDoc 与 CM 一致；结果到达不破坏组合 |
| 异步 | 延迟0/350/1000ms，旧响应最后到；点击后立即输入/开新文件 | 零过期选择/渲染提交；没有陈旧图冒用新几何 |
| 选择/历史 | Shift方向、跨块拖选、整公式选中替换、复制/剪切、撤销重做 | 源码范围准确、一次命令可整体撤销；跨行公式例外保持 |
| 长文 | 2k/20k/100k字符；密集公式；单块超8KB | 按文档尺度记录P50/P95，不主张当前已达标；不触发无限补渲 |
| 输入性能 | release桌面测输入到下一帧、长任务、编译等待 | 建议普通输入P95≤50ms且无>100ms反复卡顿；IME单独观察；先排除夹具/探针开销 |
| 呈现时延 | 最后一次输入→可见新鲜结果 | 与引擎时间分开计：正常不额外多等一轮编译；150ms/240ms策略仍可解释 |
| 多窗口 | A/B交替编译、点击、保存 | 不混几何、不混会话；现有无匹配则块首回退可接受，不能点错 |
| 正确回退 | 编译错误、未知宏、无切片、skipped、诊断块 | 源码可编辑、状态栏可解释；不吞内容/不遮错误 |

公式恢复和结构化改动均以数据正确优先。不能为了像 Typora 引入 Markdown 符号、改变 Typst 语义或偷偷改保存行为。

| Tiptap/ProseMirror | schema与Markdown转换需要明确内容模型 | 本次不迁移；任意Typst源码无损往返仍需自行设计。见 [schema](https://tiptap.dev/docs/editor/core-concepts/schema)、[Markdown模块](https://github.com/ProseMirror/prosemirror-markdown) |

不采用 KaTeX/MathJax 替换 Typst 数学，也不把浏览器 DOM 当第二份正文。前者改变公式语言与排版，后者扩大源码映射、保存、撤销的风险；首要视觉问题可以在现有体系内解决。
