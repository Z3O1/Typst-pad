## 写作模式的局部块级渲染（“可编辑正文 + 复杂块切片”）

写作模式下，**纯 markup 的 `Paragraph` / `Heading` 始终保留为 CodeMirror 真实文本**，标题、粗体、斜体与行内公式由文字装饰或局部 widget 呈现；列表、代码、表格、宏等复杂或无法可靠识别的内容继续使用 typst 引擎切片，光标进入复杂块时展开源码。这样正文点击后可直接输入与选择，复杂内容仍保留真引擎排版和源码退路。调研与实测见 `docs/文档模式渲染保真-调研.md`；详细交接见 `docs/写作模式块级渲染-现状与交接.md`。复杂切片仍**没有铺“每字形 span 的文字层”**，因此其中的浏览器查找 / 拼写检查 / 无障碍能力仍受限。

  - **“纯 markup”的判据**：块内没有 `code` / `raw` / `comment` 区域（`isDirectlyEditableTextBlock`：`scanNonMarkupRegions` 的 region 与块区间不相交，二分查找，别退回线性扫描）。**`string` 区域不算复杂** —— lexer 把 `"` 全文登记成 string 是为了公式扫描（`"$5"` 不当公式，见 `typst-lex.ts`），而 markup 里的 `"` 是 typst 的弯引号；把它算作复杂内容会让写了一句 `他说"你好"` 的正文整段退回切片、未闭合的引号更会带走其后所有段落（2026-09-22 审查发现，已修）。真在代码里的字符串一定被外层 `code` 区域包住（`#let s = "x"`、`#image("x.png")`），所以放宽 `string` 不会漏掉代码。
  - **已知代价**：引擎在 markup 层之外渲染的东西 —— `@引用`、`<label>`、`--`/`---`/`...`/`~`/`-?` 这类简写、`\` 转义、英文单引号 —— 在可编辑正文里**按源码显示**（markup 装饰层只认标题/粗斜体/行内代码/列表/链接）。要恢复真排版得给这些构造补装饰（未做）；把它们算作“复杂”反而会让几乎所有英文段落退回切片，得不偿失。

- **链路**：`runCompile` 写作模式走 `compile_blocks`（Rust `block_geometry::compile_blocks`：整篇编译一次 → 每个源块切一块 SVG），源码模式仍走 `compile_doc`。后端没有这个命令（浏览器桩 / 旧安装包）时返回 `unavailable`，**自动退回原路径**。
- **装饰**在 `live-preview.ts` 的同一个 StateField 里生成（块切片 + 公式 + 标记），因为 **CodeMirror 不允许重叠的 replace 装饰**——被复杂切片盖住的公式/标记装饰必须跳过（`insideCovered`）。块区间仍由 `block-plan.planBlockCovers` 铺满全文、首尾相接；随后 `isDirectlyEditableTextBlock` 把纯 markup 正文/标题强制标为展开，仅让复杂块建立切片。
  - **"块区间铺满全文"这句话要分清口径（别写成错的断言）**：`source_blocks` 是按 typst 语法树顶层分的，**空行、无输出的块（`#set`/`#show`）不属于任何块** ⇒ `blocks` 之间有洞是正常的；真正"铺满全文、首尾相接"的是**前端按行建的格子** `planBlockCovers` 的输出（每格从自己第一行行首到下一块第一行行首）。所以断言"铺满"要断言在 covers 上，别断言在 `blocks` 上。
- **窗口化不可省（实测数据）**：逐块 SVG 各自复制字形轮廓，约 **58 字节/源字符**——2 万字符文档全渲一次 11.5MB / 3.7s（debug），而这是每按键一次的代价。所以只渲**视口窗口**内的块（视口 ± 4000 字符；短文档 ≤ 8000 字符全渲），窗口外的块按"块类型 + 源码文本相同"沿用上一轮切片（`carryOverCrops`），滚动到没渲过的区域先显示源码、去抖 150ms 后按新窗口重编译。**别改回"每次都全渲"。**
  - **窗口化是"按块"的，所以单块自己也得上限（PR #60 审查第 7 条）**：`in_window` 判的是"这一块的源码区间与窗口相交"，于是一块如果自己就很大（**没有空行的长段落**、2000 行围栏代码块），它永远"在窗口内" ⇒ 每按一个键整块渲一遍（58 字节/源字符 → 6 万字符的代码块就是 3MB 级的一次按键）。现在超过 `MAX_CROP_SOURCE_BYTES`（**8KB**，与前端"短文档 ≤ 8000 字符全渲"同一量级）的块**只回几何、不渲图**：`skipped = true` + `svg = ""`，`found` 仍为 true（格子边界照旧）。
    - **前端必须把 `skipped` 与"缺切片"分开**：`notifyBlocksNeeded` 里"要补渲"的判据是 `found && !skipped && svg === ""`（`live-preview/block-decorations.ts` 写成 `!block.found || block.skipped || block.svg !== ""` 就 continue），`block-plan` 的 `renderable` 同样排除 `skipped`。不排除就会对同一个块**每 150ms 重编译一次**。
    - 半开窗口（只给 `want_from` / `want_to` 之一）**语义就是全渲**（写成显式的 match 分支，别让它看起来像漏判）；前端只会两端都给或都不给。
    - 两侧的锁：Rust `oversized_block_is_skipped_not_rendered`（1000 行代码块 → skipped + 空 svg，同文档的段落照常渲）；前端 `live-preview.test.ts` 两条（skipped 不要求补渲 / 没 skipped 仍然要求补渲）+ `block-plan.test.ts`（skipped → `renderable: false` 且**不是** `noOutput`）。
    - **还没做的**：把"超大块"按视口只渲**可见那一段 y 带**（widget 高度仍占满整块、图只画一条带），那样超大块也能有切片而不只是显示源码。要做的话得让 `BlockCrop` 多带"带内偏移 / 整块高"，前端再把图画在盒子里对应的位置 —— 现在的取舍是"显示源码"，因为超大块本来就要编辑。
  - **"有没有块缺切片"要直接看块表，不能看 `buildBlockCovers` 的结果**：那条路会把"能渲染但这一轮没拿到 svg"的块标成 `revealed`，于是 `!cover.revealed` 永远为假——**滚动到没渲过的区域一次都不会补渲**。判据只该是 `found && !skipped && svg === ""`。另配"同一个窗口不重复编译"的防抖（`lastBlocksWindow`）。
- **编辑期间必须让块表"跟着走"**：块表与切片是上一次编译的产物（**旧文档坐标**），插入换行会改变行结构，旧坐标放在新文档上会落到错误的行 ⇒ 旧切片盖住被移动的正文（实测"在开头插入新块后，`第二段。`整行凭空消失"）、或同一段既在切片里又露成源码。修法：**每次编辑都跑 `remapBlocksThroughEdit`**（前后缀差分：没被碰到的块原样/平移、被碰到的退回源码、改动落在块之间时归给"格子里放着它的那一块"），跑完 `blocksVersion++` 让编辑器按新表重建装饰。**别退回"编译失败时才平移"。**
  - **`planBlockCovers` 必须容忍越界**：过滤掉落在当前文档之外的块，**绝不抛异常**（旧块起点越过缩短后的文档会抛 `RangeError`，装饰整篇退化成源码，且在 ViewPlugin 里抛出会被 CM 记成 "CodeMirror plugin crashed"）。
  - **块表过期时仍然沿用旧表，不整篇退回源码**：编辑只发生在已展开的那一格里，其它格的覆盖区间首尾都落在空白处（块的源码终点 / 上一块的源码终点），偏一两个字符既不会露出来也不会吃掉正文；而"过期就整篇退回源码"会让每敲一个字都闪一次源码。编译结果回来后（数十毫秒）整表替换。（这条原先挂在一个从不被调用的 `isBlockTableFresh` 上，2026-09-19 清死代码时把函数删了、理由挪到这里。）
- **源码透镜的字号/行距/字体都必须跟随文档（用户：「不要光标在哪里哪里就变大了」）**：复杂块是引擎切片、可编辑正文是真实文本，两者不一致时光标一进某一块字就变大（旧值：编辑区固定 16px / 行高 1.9，而切片是 11pt = 14.6667px / 行高 1.65）。现在 Rust 侧 `document_text_pt` 按**字符数取众数**算出正文字号、随 `compile_blocks` 的 `textPt` 返回，前端挂成 `--write-doc-px`（`pt × 4/3`），写作模式 `.cm-editor` 字号取它、`.cm-content` 行高取 typst 的 `par.leading`（0.65em → **1.65**）。缺省 14.6667px（旧后端 / 桩也对得上）。**别把字号写死回去**。验收：`writing-mode-scenes.mjs` 的「光标进出块时页面不许变高」四条**别删**。
  - **字体是同一套打包字体**：切片是 typst 用打包字体（Libertinus Serif + 思源宋体子集）排的，启动时把这些字体装上（Rust `bundled_font` 读 `resources/fonts/`，raw IPC → `FontFace`；字体本来就随应用分发，不增加体积），`--write-font-stack` 与 typst 默认族**同序**：`Libertinus Serif → Noto Serif CJK SC → 系统宋体兜底`。装不上就什么都不做、退回系统族。验收：`writing-blocks.mjs` 第 17 组 + `editor-font.test.ts` + `scripts/editor-fonts.test.mjs`。
- **公式字号 = 正文字号，跟着模式走**：写死 12pt 会让光标所在块里的公式比周围正文大 9%、也比同一公式在切片里大。现在由父组件按模式给：写作模式 = 文档 `textPt`（`Editor.svelte` 的 `mathSizePt`），源码模式兜底 `MATH_TEXT_PT = 10.5`（内联渲染只在写作模式开，那条分支只是兜底）。字号随 `MathRequest.sizePt` 传给父组件，公式夹具导三档字号，验收 `writing-blocks.mjs` 第 18 组锁"sizePt = 正文 px × 0.75"。
- **文档切换（打开/新建/重读）必须 `resetBlocks()`**：旧块区间套在新文档上会**盖住正文**（比公式缓存过期的危害大得多）。
- **暗色**：切片是白底黑字（页面自带白底），整体 `invert(1)` → 深色纸浅色字；文档自带颜色会被反掉，与公式 widget 同一策略。
- **坑**：块切片的 `Decoration.replace({block: true})` 区间**必须落在整行边界上**——只给"块最后一个字符"当终点时，Chromium 里 CM **既插入 widget 又保留原文**（jsdom 用例恰好都落在整行上，所以单测全绿、只有真浏览器验收抓到）。格子按"整行"算，光标落在边界上时只展开后面那一格。
- **块与块之间的空行归「上一块」的格子**：每格 =「自己的第一行行首 → 下一块的第一行行首」（末格到文档末尾）。**别改回"空行归下一块"**：那样在行尾按 Enter 后（光标正好落在新空行行首 = 上一块切片的结尾），CM 会把光标定位到 widget 自己身上、画到正文列最右边（实测 `coordsAtPos(head).left` 1087 → 304、`domAtPos` 从 `.cm-content` 变回 `.cm-line`）。`remapBlocksThroughEdit` 的"空行上打字"落点要跟着用"末尾在改动点之前的最后一块"。验收 `writing-blocks.mjs` 第 16 组。
- **分块判据必须跟 typst 语义走，不能看"是否独占整行"**：`$x$`（定界符内侧无空白）是**行内**公式，哪怕独占整行也不打断段落；只有 `$ x $` 才是行间公式。`` `code` `` 是行内 raw，只有围栏才是块。按"独占整行"分块会让这些块的带互相重叠（公式挤成一团）。回归测试 `block_partition_matches_typst_semantics`。
- **块的纵向区间必须"夹紧到 y 序下一个块的顶"**：typst 允许把内容排到远处（脚注正文在页底、`#place` 在别处），块的墨迹包围盒是并集 ⇒ 带脚注的段落会得到伸到页底的高盒子，把后面几块的中点切带压扁、切片被丢弃（代码块/表格重复出现）。现在第 2b 步把每块 bottom 夹到下一块 top，带高退化时留最小带而**不是丢块**。
- **竖直移动 = 代码模式的语义（用户：「我希望光标移动和代码模式的光标移动一样」）**：CM 的 `moveVertically` 逐像素扫到**文本行**才停，而 `posAtCoords` 对 widget 直接跳过 ⇒ 切片全是 widget 时"往上"会一路跳到位置 0。规则两条（纯函数 `block-plan.crossesCollapsedCover` + `sourceVerticalTarget`）：① 默认走法**没跨过未展开的切片** → 交回 CM 默认；② 跨过了 → 按**源码行**走一行（空行停一拍、列保留，落点在切片里就把那一块展开），列先用字符列估、再用真实几何校正。**Shift+↑/↓ 也一并接管**。**别退回"一次跨一整块"**（会跳掉空行、丢掉目标列）。验收 `writing-blocks.mjs` 第 8 组**别删**。
- **翻页（PageUp/PageDown，含 Shift 扩选）自己实现**：CM 默认翻页同样跳过 widget。做法与 CM 的 `cursorByPage` 同源：位移取 CM 的 `clientHeight - 5`，把光标当前屏幕高度平移一屏作为查询点，再用滚动目标把光标钉回原屏幕高度；位移**不按"还剩多少滚动余量"夹**（夹成 0 会把按键交回默认 → 跳到文档末尾）；到头时由 `posAtCoords` 夹到文档首尾。没有块级渲染时交回默认。验收 `writing-blocks.mjs` 第 10 组。
- **打字期间不编译（用户：「输入手感很差」）**：写作模式每次按键都会整篇编译 + 窗口内每块渲一张切片（debug 几十~几百毫秒），三个编译命令共用一把互斥锁，实测打 12 个字符会发出 12 次 `compile_blocks` + 12 次 `compile_math`。现在写作模式编译**去抖 150ms**（`WRITE_COMPILE_DEBOUNCE_MS`；源码模式仍立即），且有公式要渲时把块编译再往后推（`MATH_COMPILE_HEADSTART_MS = 240`）。改完实测 12 个字符 → 1 次 `compile_blocks` + 1 次 `compile_math`。**别把去抖去掉。**
  - **`writeCompileTimer` 跑完必须置回 `undefined`**：它同时是"有没有挂着的块编译"的判据（`math-queue` 的 `deferBlockCompile` 据此把公式优先级提前）。不置回的话每个公式请求都会在 240ms 后再排一次整篇编译。
  - **`compile_blocks` 的 `blocks` 键永远要发**（哪怕失败时是空数组）：前端用"`blocks` 是不是数组"区分「后端没实现这个命令」与「这一次编译失败」。它原先是 `skip_serializing_if = "Vec::is_empty"`，而 `fail()` 正是把它置空 ⇒ 失败 JSON 里没有这个键 ⇒ **真机上任何 typst 错误都被读成"后端不支持"**。前端那个"形状不对就 unavailable"的判据现在**只看 `ok` 键**；桩**故意不发** `blocks` 来锁这条路径。Rust 单测 `failure_output_always_carries_blocks_key`。**与 `path:null` 是同一类陷阱：桩按契约写、真后端不这么发。**
  - **块级结果回来时必须确认"请求时的那份文档 == 当前文档"**：写作模式的编译是去抖的，这期间 `compileSeq` 不会自增 ⇒ 旧结果会被套到新文档上、字节偏移错位。`runCompile` 里记 `requestDoc`，不一致就丢弃。
  - **输入法合成期间不许重建装饰**：`blocksVersion++` 每次编辑都发生，而 Editor 里"重整装饰"的 `$effect` 必须有 `view.composing` 守卫——合成中途换掉 widget DOM 会把候选串与合成状态一起弄坏。合成期间攒着、`compositionend` 后补一次刷新；验收第 19 组走 CDP 真实合成路径。
  - **光标所在的公式不请求渲染**：`collectRequests` 里先 `selectionTouchesRange` 跳过光标/选区里的公式——那一刻它是源码形态，否则"每敲一个字编译一次公式"。
- **点击定位**：点切片 → 光标落到**点到的那个字符**。链路 = 切片内相对位置 → 页面坐标（pt，`block-hit.ts`，只依赖 DOM 实测矩形）→ Rust `block_hit_test` 在排版帧里找最近的字形（`block_geometry::pick_hit`，几何来自上次编译的 `HIT_CACHE`，不进编译互斥锁）→ 字节偏移 → CM 位置。任何一步失败都退回"落到块首"，**绝不吞掉点击**。三道闸门：块表必须与当前文档一致（`writingBlocksDoc === doc`）、是**精确**的（`writingBlocksExact`）、**几何编号对得上**。
  - **`HIT_CACHE` 是进程级的，必须带几何编号**：应用支持多窗口，窗口 A 编译完、B 再编译一次之后，A 里点击会拿 **B 的排版几何**去找最近字形、**点错字而不报错**（前端那两道闸门都是每窗口的）。现在 `compile_blocks` 返回自增的 `geometryId`，`block_hit_test` 带回来比对，对不上 → 退回"光标落到块首"；不传编号（旧前端 / 内部探针）仍按老行为。Rust 单测 `hit_test_refuses_geometry_owned_by_another_compile`；`writing-blocks-hit.mjs` 的 136 次点击真的走这条校验。
- **滚动锚定不要自己写 `scrollDOM.scrollTop`**：CodeMirror 的 measure 循环里自己也有锚定，我们在 mousedown 里算完 `scrollTop += Δ` 之后它还会再改一次（实测设 1771、被拉回 1680，点击落点偏 91px）。改成把 `EditorView.scrollIntoView(pos, { y: "start", yMargin })`（`scroll-anchor.ts`）放进**同一个事务**后偏差 4px。装饰重整引起的高度变化交给 CM 自己的锚定，我们**不**再加一层。
- **编译失败不整篇作废**：`remapBlocksThroughEdit` 用前后缀差分判定哪些块没被碰到——之前原样、之后平移、相交的退回源码（区间**放宽**到并集：只多显示源码，绝不盖住新打的字）。**输出必须仍然铺满全文。**
- **诊断所在块不许被切片盖住**：`revealBlocksWithDiagnostics` 按**格子**区间判相交（格子含块前后的空行），在 `applyBlockSelection` **之后**跑。
- **切片上的鼠标行为统一由 `mouseSelectionStyle` 接管**：点击、拖选都走 `live-preview/block-drag.ts` 的 `CropSelection`（`view`/`event` 里不是切片就返回 null，交回 CM 默认）。
  - **别在 widget 上自己挂 `mousedown`**（会与 CM 的鼠标选择抢同一次事件）；也别用 `instanceof HTMLElement` 判"指针在不在切片上"——指针多半落在切片内部的 `<svg>` 上（SVGElement），用 `Element.closest(".cm-block-crop")`。
  - **拖动期间必须"冻结版式"**：拖动中一旦真的落选区，被选中的块会展开成源码、版式一变指针底下的内容就换了（实测拖到一半位置倒着走）。所以拖动期间只更新内部落点 + 画一个半透明"扫过"色块，**松手那一次**才把真选区交出去。
  - **单击不要听松手**：`MouseSelection.up()` 只在 `dragging == null` 时才重新问 style，且问的是上一次 move 事件，所以松手要自己听（捕获阶段的 document `mouseup`），但**单击（没拖动过）时松手什么都不做**（按下那次解析已经把光标放好了，松手时版式已变，再解析会落到别处）。
  - **Shift+点击 / Shift+拖选切片 = 扩选**：`CropSelection.commit()` 要与 CM 默认同口径，固定端（`extendFrom`）= 原选区（空选区时是光标）；原先一律 `EditorSelection.single(anchor, head)` 会把原选区收掉。验收 `writing-blocks.mjs` 第 20 组。
  - **`EditorSelection.single()` ≠ `EditorSelection.range()`**：给 CM 的 `MouseSelectionStyle.get()` 返回值必须是 **EditorSelection**（要有 `.ranges`/`.main`），交 `SelectionRange` 会让 CM 内部读 `undefined.length` 直接抛、拖选无声失效。
- **整块被选中时"不展开"（用户：「选中整个代码块不要展开」）**：选区**完整盖住**某一块（`sel.from ≤ block.from && sel.to ≥ block.to`）时不展开，改用 `cover.selected` 给切片挂淡色底（`.cm-block-crop-selected`）；只盖住一部分才展开源码。**注意**：正文/标题块自 2026-09-22 起已是真实文本、不再建切片，所以这一条与淡色底只对**复杂块**生效（`cover.selected` 对正文块是只写不读）。**两条硬约束**：
  - **光标（选区 head）所在的那一块必须展开**：整块不展开时那一格是图片，图片里没有真实文本，CM 收不到输入事件 ⇒ **Ctrl+A 之后打字一个字都进不去**。所以"整块选中不展开"只对光标不在里面的块成立。
  - 因此"在代码块里拖选整块"还是得展开——那就**把两行围栏藏起来**（`buildFenceHidingDecorations`，整行替换含行尾换行），代码正文仍是真实文本。
  - 非空选区时**不做**"兜底展开第一格"；兜底只在空选区（光标）时生效。
  - **染色层必须铺在切片 SVG 之上，而且不许有描边**（用户截图说「太丑了」）：切片的 SVG 自带不透明白纸底，给容器加 `background-color` 看不见；现在 `toDOM` 里额外插一个 `.cm-block-crop-tint`（`position: absolute; inset: 0; pointer-events: none`，**排在 SVG 之后**），颜色取 CM 自己的选区底色（≈ `rgba(122,112,205,0.3)`），**不要 outline**。`.cm-math-selected`（公式）同理。
- **链接可点**：typst 的 `#link("https://…")[文字]` 画成 `FrameItem::Link(目标, 方框)`——**不带源位置**但带目标与方框，Rust 侧收成"带内相对 pt"的热区（**夹到带内**），前端在切片上铺一层透明 `<a>`（百分比定位，与 SVG 等比缩放天然一致），点击后交给 opener 插件。只收 `http/https/mailto`（前端另有一道白名单，`javascript:` / `data:` / `file:` 丢掉）；页内 `#link(<label>)` 属后续工作。
  - **链接热区的 `mousedown` 必须 `preventDefault`**：只 `stopPropagation` 的话浏览器会把焦点给这个 `<a>`，编辑区失焦 ⇒ 点完链接回来**一个字都打不进去**。验收判据必须是"焦点就在 `.cm-content` 上"（只判"焦点在编辑区里面"是恒真的——热区 `<a>` 本身就是 `.cm-content` 的后代）。
- **块粒度**：列表已经**每项一块**（`ListItem` / `EnumItem` 各自成块，嵌套列表留在父项那一块里）；**表格仍是整块**（按行切会把表格线切开，有意不做）。
- **切片 DOM 上有 `data-block-from` / `data-block-kind`**：浏览器验收靠它把"夹具里的第几块"与"页面里的哪张切片"对上。别删（`writing-blocks-hit.mjs` 依赖它）。
- **没有输出的块整格隐藏（用户选定「完全隐藏，和 PDF 一样什么都看不到」）**：`#set` / `#show` / `#let` / 纯注释行这类"规则"在真排版里没有输出，所以写作模式整格隐藏（`buildHiddenBlockDecorations`：整行 `Decoration.replace({block: true})` 不带 widget，连块尾空行一起藏），光标/选区进去才展开成源码。**关键区分（别写错，会藏掉用户刚打的字）**：`Block.noOutput` 只在"这一次成功编译、引擎确实什么都没给这一块"时为 true；"块表过期 / 编译失败"那种不可渲染必须在 remap 里把 `noOutput` **清成 false**（那种块照旧永远展开源码）。验收：`writing-mode-scenes.mjs` 的四条 + `block-plan.test.ts` / `live-preview.test.ts` 各两条。
- **阶段 3 验收别删**：`writing-blocks.mjs` 第 12 组（`&blockslow=1` 用 350ms 假延迟模拟真机编译窗口：插入新块后正文一行都不许丢、不重复、控制台干净；含"文档大幅缩短"旧坐标越界那条）、第 13 组（12 个输入动作，每个之后都要"标记词看得见 + 一行不丢 + 不重复 + 切片回来 + 控制台干净"；去掉修复时 9/12 红）、第 14 组（拖选跨块 + Ctrl+C + 拖选后打字替换）、第 15 组（淡色底看得见 / 没有描边）、`block-plan-edits.test.ts`（68 项：4 篇文档 × 每个位置 × 17 种编辑动作 → 四条不变量）。
