## 测试

- 前端 vitest + jsdom，`include: ["src/**/*.test.ts", "scripts/**/*.test.mjs"]`；scripts 是普通 JS + node 内置模块，**刻意不进 TS program**（否则每个参数都要 JSDoc 或装 `@types/node`），所以不参与 svelte-check。`server.fs.allow: [".."]` 覆盖仓库上级目录（junction 场景的教训）。
- **已删除的低价值测试（勿凭"补覆盖"再加回来）**：`file-ops.test.ts`（只测 `.typ` 后缀匹配，真路径安全在 Rust）、`debug.test.ts`、`context-menu-utils.test.ts` 的 `computeMenuPosition` 收边 5 项（更复杂的限宽分支由 `popover-utils` 覆盖）。
- **Rust 单测里"全局缓存"的坑**：`block_geometry` 的命中几何是**进程级全局**（`HIT_CACHE` 只留最近一次 `compile_blocks`）。生产路径没事，但 **cargo test 并行跑**时后者会覆盖前者，症状是"单测单独跑绿、跑全集红"（实测：`hit_test_on_real_layout_maps_edges_to_block_bounds` 期望 `Some(0)` 拿到 `Some(2)`，正好差一个前缀的长度）。**凡是写/读这块缓存的用例都先拿 `HIT_CACHE_TEST_LOCK` 串行**（`let _hit_cache = hit_cache_guard();` 放在函数第一行）；`pick_hit` 那种纯函数用例、以及走 `probe_blocks` 的用例不受影响（探针不碰 `HIT_CACHE`）。**PR #61 审查时这条曾被打破**：`oversized_block_is_skipped_not_rendered` / `footnote_doc_keeps_every_band_and_stays_contiguous` / `dump_long_doc_blocks` 三个写缓存的用例没拿锁（前两个还会与持锁读者并行），现已补齐。`#[ignore]` 的四个 `dump_*` 探针仍不拿锁 —— 它们只被 `cargo test <名字> -- --ignored` 单条过滤着跑，不会有并发对手，**别拿它们当"可以不拿锁"的先例**。
- **本机跑 `npm run fixtures:blocks` 要让 cargo 在 PATH 上**：脚本里是裸 `cargo`，本机在 `~/.cargo/bin`——不补会产出空的夹具（后面几套真实产物验收全变成"没有夹具"）。补法：`PATH="$HOME/.cargo/bin:$PATH" npm run fixtures:blocks`。
- **空夹具 = 假绿，两处都要挡住**（PR #61 审查第 3 条）：`fixtures:*` 用 `2>/dev/null` 吞掉 cargo 的错误，而 **cargo test 过滤器命中 0 个用例时退出码是 0** ⇒ 会写出一个空的 `.browser-check/*.json`；消费者脚本若只 `for (const fx of fixtures)` 就会**跑 0 项断言、退出码 0**（看着全绿）。现在两道防线：① `package.json` 的 `fixtures:blocks` / `fixtures:math` 在数组为空时 `process.exit(1)`（并打印"用例名被改 / 编译失败？"）；② 四个消费者脚本（`writing-blocks-visual` / `writing-blocks-hit` / `writing-mode-scenes` / `wysiwyg-visual`）读到空夹具（`hit` 那套是"没有探针"）即硬失败。**新增消费夹具的脚本时照抄这段。**
- Rust 单测覆盖：中文+数学文档端到端编译、字体注册（7 个文件 + 族名）、语法错误诊断（1-based 行列 + endLine）、相对 include / 项目根放宽、JSON 序列化契约（camelCase 键名、主源不发 `path`）、@local/@preview 包（缓存命中不下载 / miss 下载 / 404 与网络失败区分 / 路径穿越与损坏归档防御，均用临时目录，不触真实用户目录与网络）、块级渲染（分块判据、切带、命中校验、文档字号）。
- 前端单测覆盖：`typst-engine`（invoke 契约映射 + 诊断转换，invoke/dialog 以 vi.mock 断言入参）、`diagnostics-utils`、`error-list`、`doc-utils`、`editor-keymap`、`menu-keys`、`popover-utils`、`persistence`、`svg-paginate`、`pdf-export`、`preview-scale`、`write-commands`、`zoom`、`zoom-controller`、`update-utils`、`update-flow`、`update-notes`、`file-flow`、`math-queue`、`window-flow`、`block-state`、`block-plan*`、`live-preview`（jsdom 里真挂 EditorView）等；所见即所得链路另有 `typst-lex` / `markup-ranges` / `math-context` / `typst-scan-fuzz`（120 份固定种子随机文档 + 15 组病态输入，断言不抛异常、区间有序不越界不重叠）。**坑**：jsdom 下挂视图时光标默认在 offset 0，会落在构造内部而触发"展开"，测隐藏效果必须把光标放到构造之外。
- **别在 `<script>` 区里写 `<style>`（或 `<script>`）这种标签字样 —— 哪怕是 `//` 注释**：svelte2tsx 是按字符串找样式块起点的，命中注释里的字样就会把文件切错，于是 svelte-check 报一句看着毫不相干的 ``Error: `<script>` was left open``（指向 `</style>` 那一行）。要提页面样式块就写"页面样式块"。（2026-09-18 拆组件时踩了两次。）
- **拆组件时页面里那条 `* { box-sizing: border-box }` 要跟着搬**：Svelte 把 `*` 编译成**页面自己的作用域类**（`.svelte-<页面hash>`），而 `box-sizing` **不继承** —— 页面里那条命中不了子组件里的元素，组件里的元素会静默退回 `content-box`。实测（2026-09-19，PR #62 拆 `+page.svelte`，400px 视口）：`.settings-modal` 从 360px 变成顶满整宽（`max-width:90vw` 作用在 content box 上，再加 24×2 padding + 1×2 border 就越过视口），`PreviewPane` 的 `.preview-error`（`width:100%` + 内边距 + 边框）在 `overflow:auto` 的容器里横向溢出；同一类还有 `.error-popover`（520→538px）、`.modal`（`min-width:320px` ⇒ 370px）、`.about-modal` / `.update-modal`、`.update-progress`（`height:6px` + 边框 ⇒ 外高 8px）。**只有"显式宽高 + padding/border"的元素会变**，靠父容器拉伸的元素量不出差别 —— 所以别指望现成的验收脚本抓它（五套全绿也可能中招）。**修法：每个从页面搬出来的组件在自己的 `<style>` 里各写一条 `* { box-sizing: border-box; }`**；别图省事塞进全局 `modal.css` —— 那会把 `Editor` / `MenuBar` / `ContextMenu` 一起从 `content-box` 改掉，它们拆分前本来就没有这条。复核：真浏览器读 `getComputedStyle(el).boxSizing`，或直接量 `.settings-modal` 在 400px 视口下的宽度（应为 360 而不是 400）。
- **浏览器端交互验证（无显示器环境下的验收手段）**：`scripts/browser-check/`（零依赖 CDP 驱动）。
  - **端口**：脚本默认打 `http://localhost:1420/?browserdev=1`，而 1420 也是 `tauri dev` 的端口——用户自己开着桌面应用时会被挡住。换端口跑即可（`BROWSER_CHECK_PORT` / `BROWSER_CHECK_URL`，由 `cdp.mjs` 导出的 `DEV_URL` 读取；1420 在 `vite.config.js` 里写死 + `strictPort`，宁可报错也不自动换端口）。
  - `cdp.mjs` 两种起法：① Windows Chrome（`--headless=new --no-proxy-server --remote-debugging-port=9333 --remote-debugging-address=0.0.0.0 --user-data-dir=…`，**镜像网络**下 WSL 才能直连）；② WSL 里的 Linux Chromium（Playwright 缓存里的 `chromium_headless_shell-*`，见「环境备忘」）。
  - 各套件验什么（计数即当前基线）：
    - `wysiwyg.mjs` **290 项**：公式 widget 出现/展开/恢复、标记隐藏与标题字号、链接只留文字、块级居中、文档内 `#let` 进上下文、写作模式单栏形态、格式快捷键、启动恢复、Alt 不夺焦；然后是 23~45 组——自动更新入口、界面缩放（16 项）、正文字体设置（12 项）、更新说明渲染（6 项）、缩放死区（14 项）、窄视口状态栏（4 项）、源码模式自动换行（9 项）、预览重排（10 项）、Esc/新建窗口、切换模式保持光标（5 项）、`$` 自动配对、状态栏计数徽标、启动自动检查与「稍后」抑制（13 项）、Esc 与 `Ctrl+/`、Tab 四格与回车缩进（11 项）、"编辑全程不写盘"（第 38 组）、位移不足一档的滚轮（第 40 组）、`#set page` 下也不横滚（第 41 组）、红波浪线的 `path: null`（第 42 组）、两个徽标的 Popover 一致（第 43 组）、复制诊断信息（第 44 组）、面板白底（第 45 组）。
    - `writing-blocks.mjs` **133 项**（带 `&blocks=1`）：为什么单独一套——块切片会把非光标块整块换成图片，那块里的标记/公式 widget **在 DOM 里不复存在**（设计如此），`wysiwyg.mjs` 那套断言的是"标记装饰"世界，默认开着块渲染会整片变红。桩里 `compile_blocks` **默认返回"没有这个命令"**，只有 `&blocks=1` 时给假切片。验：非光标块被切片取代（**按 `.cm-line` 判"还是不是源码形态"**，不能用 `textContent`——切片 SVG 里也有文字）、切片铺满列宽、点击锚定、块内输入、模式往返、暗色、窗口化补渲。
    - `writing-blocks-visual.mjs` **76 项**（真实产物）：先 `npm run fixtures:blocks` 导出每块真实区间/几何/SVG，再断言"切片摞起来 == 原版式"（每块高度偏差 0.01px、相邻切片首尾相接、总跨度等于真实纵向跨度、高宽比未拉伸），外加链接热区四条。**这是"和真实 typst 一样"的唯一数字证据，改块级渲染后必须跑。**（2026-09-19 实测：`npm run dev` 刚起来就开跑的那一次，"混排与 emoji"那条量到 **4** 张切片（= 旧表 2 + 新表 2）并在下一处 `TypeError` 上崩掉；重跑 3 次全绿，且在切文档后每 30ms 采样只见 `0 → 终值`、没有"两套装饰同时在场"的帧。**见到这个断言失败先重跑一次再怀疑产品** ——脚本每篇固定等 700ms，冷启动时可能量到过渡帧。）
    - `writing-blocks-hit.mjs` **27 项 / 136 次点击**（真实探针）：点击 → 精确字符全中（走 `geometryId` 校验，编号错就全红）。
    - `writing-mode-scenes.mjs` **64 项 / 9 篇**（真实产物）：按文档形态逐场景（标题层级/中文长段落/列表嵌套/公式/代码表格脚注/文档级 `#set`）断言切片数、列宽、逐块高度、相邻缝，并存截图 `.browser-check/scene-<场景名>.png`——**这几张图就是"文档模式现在长什么样"的直接证据**。
    - `wysiwyg-visual.mjs` **20 项**（真实产物）：`fixtures:math` 导出**三种字号**各一份（11pt / 12pt / 10.5pt），验行内公式基线与同行文字齐平（误差 < 1px）、渲染尺寸 = 真实 pt × 4/3、块级居中独占整行、暗色反色可见，以及第 4 组的墨迹几何体检（`getBBox()` vs `viewBox`）。**坑**：夹具 json 里没有 `ok` 字段，桩返回时必须补 `{ ok: true, ...fixture }`，否则页面里公式一直停在源码。
  - `probe.mjs`：排障小工具（导航到页面 → 打印渲染结果/页面内错误），"页面是不是坏了"先用它看。
  - **真实文档体检（任何真实 .typ 都能跑，不改源码）**：把文档存到 `.browser-check/real-scene.typ`，跑 `cargo test --manifest-path src-tauri/Cargo.toml dump_real_doc_fixture -- --ignored --nocapture`——打印 ok / 页数 / 块数 / 逐条诊断 / 逐块几何，末行输出 `BLOCKFIXTURE`；写进 `.browser-check/block-fixtures.json` 就能用浏览器验收渲染截图。
  - **实测坑（都踩过）**：① `Page.navigate` 对**相同 URL** 不重新加载（上次停在 500 错误页时会一直复现）→ `goto()` 先跳 `about:blank`；② 截图必须由 Node 写进**工作区**（写 `/mnt/c/...` 会被文件沙箱拒绝）；③ Windows 的 headless Chrome 必须加 `--no-proxy-server`，否则 localhost 被系统代理吞掉；④ 验收脚本开始前**必须清 localStorage 再重新加载**，否则上一轮遗留的「源代码模式」会让第一条断言莫名超时；⑤ 桩的"模拟引擎"页（`gotoSim`）要**先把旧页导航掉、再用 CDP `Storage.clearDataForOrigin` 按 origin 清**，别写成"清完立刻导航"（存档是 300ms 防抖写的，旧页销毁前会把迟到的存档写回去）；⑥ 找菜单项要限定在 `.menu-dropdown .menu-item` 里。
  - ⑦ **收尾绝不要跑 `taskkill /IM chrome.exe /F` 这种全量杀进程**（犯过：把用户自己开着的 Chrome 全杀了，用户直接炸了）。只杀**自己启动的那一个** headless 实例：启动时拿 PID 存到 `.browser-check/chrome.pid`，收尾时**按 user-data-dir 精确挑出自己那几个 PID**（`Get-CimInstance Win32_Process -Filter "Name='chrome.exe'" | Where-Object { $_.CommandLine -like '*dsh-chrome-typstpad*' }`，`powershell.exe` 要用绝对路径）。**同理适用于任何"清理现场"的动作：只动自己创建的东西**。
  - 浏览器开发模式（`?browserdev=1`）里的 `compile_doc` / `compile_blocks` 是假实现，文件/PDF 等 Tauri 命令同样是假的；**真实 typst 排版可用夹具链路上浏览器验证**，只有 Tauri IPC / WebView2 那一层必须桌面端确认。

## 代码审查：**只在"处理 PR"时做这一套**

**什么时候用**：用户丢来一个 PR 链接说"处理一下"、**别的会话 / 别的线**交来的分支要合进 main。
**什么时候不用**：自己直推 main 的日常改动——那是 `npm run check` + 相关单测（几秒级），改到编辑器/装饰/布局才加跑浏览器验收。**别把并发子代理那套套到日常小改上**。判断依据是"这份代码的上下文是不是我自己的"：自己写的自己知道哪里危险，别人那条线的自述与实现是否一致**必须验**。

### 两条腿必须都走，缺一条就会漏

`npm run check` / `npm test` / `cargo test` / 五套浏览器验收**全绿**的 PR，仍可能带着"真机根本走不到"的 bug——因为**桩是按契约写的**，真后端不这么发（PR #60 的 `blocks` 键、0.8.3 的 `path: null` 都是活例）。所以：**跑起来证明"断言下的行为对"，读代码找"断言之外真机会怎样"。**

### 腿一：并发子代理「读代码」——按风险面切，边界故意重叠

一次消息里发出去（各自独立上下文、互不可见），**通常三个**：

1. **后端 / 引擎**：IPC 契约（成功与失败两种形状）、panic 逃逸、缓存键与生命周期、锁与线程模型、路径穿越、O(n²)。
2. **前端核心**：仓库红线逐条核对、编辑态不变量（旧表 vs 新文档）、选区/焦点语义、每按键的全文档扫描。
3. **集成 / 文档 / 验收脚本**：**会不会压坏上一个发行版的功能**、退回路径、脚本里的断言是不是真断言（有没有 `if (x)` 式静默跳过）、文档数字与代码是否对得上、仓库卫生（删掉的文件真没人引用、没混进临时文件）。

**边界故意重叠**：同一条 bug 被两个角度分别撞到才算独立证据（PR #60 的 `blocks` 键是三个互不可见的审查者 + 我自己复核 = 四条独立证据）。

**每份 prompt 必须自带这六段**（子代理看不到本会话）：

- ① **git 现场**：`HEAD` 是哪个提交、基线是 `main` 的哪个提交，点明"`main` 是 HEAD 的祖先 ⇒ `git diff main HEAD -- <路径>` 就是 PR 改动"。
- ② **PR 是什么 + 它自称做到了什么**（不写这段，模型会去审"设计对不对"，而不是"实现与自述对不对"）。
- ③ **本仓库的红线原文**（`editorDoc` 实时镜像 / 装饰 `b>a` 且必须在 try/catch 内 / 留白挂 `.scroller` / 不许夺焦 / 版本与发版纪律 / 不许动签名密钥）——**这段最值钱**：把"这个仓库踩过的坑"变成审查清单。
- ④ **5~6 条具体问题**，要可判定（"`compile_blocks` 失败时返回什么形状"，不是"你觉得实现好不好"）。
- ⑤ **证据格式 + 反向要求**：每条给 `文件:行号` + 现象 + 触发条件 + 最小修法，按严重度排序；**每个类别都要明说"这一类没发现问题"**（不写这句，模型会为凑数编问题）；不许泛泛建议"加注释"。
- ⑥ **只读纪律**：不许改文件、不许 `git checkout`/`commit`/`stash`；**也不许跑 `npm test` / `cargo` / 浏览器验收**（会和主 agent 抢 CPU、`src-tauri/target` 与 1425/9333 端口）。

### 腿二：主 agent 自己「跑起来」（与腿一并发，不阻塞回合）

照「测试」那节跑全套：`npm run check` → `npm test` → `cargo test` → `npm run fixtures:{blocks,math}` → 五套浏览器验收。
**本机跑法**（一次性脚本 `.browser-check/prXX-verify.sh` 最省事：自己起 dev server + headless chromium、跑完自己关，日志重定向进 `.browser-check/prXX-verify.log`）：`PATH="$HOME/.cargo/bin:$PATH"`、`BROWSER_CHECK_URL='http://127.0.0.1:1425/?browserdev=1'`、Linux chromium 用 Playwright 缓存里那个。跑完把每个套件的**计数**记下来与 PR 自述逐条对。

### 复核纪律（别把子代理的结论直接转述给用户）

- 最高杀伤力的那几条**自己读代码复核**（PR #60 我亲自确认了 `skip_serializing_if` + `fail()` 置空 + 前端形状检查的先后顺序，纯 serde 语义，不用跑就能定死）。
- **只出现一次、自己又没复核的，一律降级**（进"一般/建议"，不许写进"严重"）。
- 报告里要分清"**我验过的**"与"**只转述的**"，并把方法自身的局限写进去：读代码 ≠ 执行证明；不是全量逐行审；模型会漏也会误报。

### 结论落盘：写到 PR 评论里，不要只留在对话中

`gh pr comment <n> --repo Z3O1/Typst-pad --body "$(cat .browser-check/prXX-comment.md)"`（body 先写成文件再读进变量，中文与换行才不会被 shell 吃掉）。评论里要有：**独立复跑的计数表** + 按严重度排的清单（每条带 `文件:行号` 与最小修法）+ 明确写"哪些类别没发现问题"。

### 审查与合并的关系

- **审查发现的问题不阻塞合并**，除非是"合了会坏掉**已发布**功能"那一类（新功能线自己的 bug 不是阻塞项）。
- **合并方式：多条提交的功能线用 merge commit，单笔小改动 squash 无所谓**。判据是"提交历史本身有没有信息量"（#60 那 30 个提交是这条线的"故事"，squash 会打断文档里对它们的引用）。
- **合并后不删分支**：那条线还在继续用。
- **修复归属由用户定**：清单交回原线、还是我在 main 上修，都要先问。
- 审查与合并都**不碰版本号 / CHANGELOG / tag / Release**（红线 11 照旧）。
