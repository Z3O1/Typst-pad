## 所见即所得（编辑器内联渲染）数据流

形态 = Typora / Obsidian Live Preview：**源码仍是唯一真相**，编辑器在非选区处把可渲染范围换成渲染结果，光标/选区进入即展开源码。

- **范围识别**：`typst-lex.ts` 先把文档切成 markup / code / raw / comment / string 区域（`#let a = b*c*d`、`#let s = "$5"`、`// $x$`、`` `$x$` `` 都不参与标记识别；代码里成对 `[...]` 是内容块，内部回到 markup）；`math-ranges.ts` 在 markup 区里认 `$...$`（内侧两侧空白 = 行间公式），`markup-ranges.ts` 拆标题/粗斜体/行内代码/列表符号/链接。**保守优先：宁可漏渲染，不可误渲染。**
- **公式渲染**：`live-preview.ts` 视口内出现未缓存公式 → `onRequest` 回调父组件 → 去重 + 120ms 防抖 → `compileMath()` invoke `compile_math { body, display, context, documentPath }`（共用命令层互斥锁）→ 结果进 `mathCache`（键 = 风格 + 前缀 + 公式文本 + 字号）→ `mathVersion++` → dispatch `refreshLivePreview` 重整装饰。
- **渲染契约（`MathOutput`）**：`{ ok, svg, widthPt, heightPt, baselinePt, error }`。svg 是**贴边**（`margin: 0pt`）且**透明底**的单页 SVG；尺寸单位 pt。**基线**用「两页探针」测得（`page.frame.baseline()` 实测返回盒底，故第 2 页放同一公式 + 一个挂在基线下 100pt 的零宽盒，`ascent = H2 - 100`；外层 `#box(...)` 不可省）。
- **画布必须按「墨迹」而不是帧尺寸裁**：typst 允许把上下标画到**帧外**（实测 `$a_0$` 帧高 8.196pt、下标基线在 11.16pt），而公式页是贴边页、SVG 视口就是裁剪框 ⇒ 下标下半截、上标顶部、降部全被裁。`compile_math` 现在先量**墨迹包围盒**（`ink_bounds_of_frame`：递归 group 仿射变换、文本用**字形包围盒** `FontInstance::edges(…, TextEdgeBounds::Glyph(gid))`、图形用 `Shape::bbox(true)`），溢出时用「显式页面尺寸 + `#pad(top:)`」重编一遍（**只有溢出才走第二遍**）。注意：① 字形墨迹要用 `edges` 而不是字体度量；② 在 `#pad(top: …)` 这类**代码模式**的参数里不能再写 `#box(...)`，要写成 `#pad(top: …)[#box(...)]`。验收在 `wysiwyg-visual.mjs` 第 4 组（`getBBox()` vs `viewBox` 的几何体检）。
- **字号**：`MATH_TEXT_PT = 10.5`（Rust 与前端同名常量），源码模式正文 14px = 10.5pt，故 SVG 的 pt 与编辑器 CSS 的 pt **1:1**，前端直接写 `width/height: Npt` + `vertical-align: -(height-baseline)pt`；写作模式的字号跟着文档走（见块级渲染那节）。改字号要两侧同步。
- **暗色主题**：typst 产物是黑字透明底，暗色下看不见 → widget 带 `cm-math-dark` 类整体 `filter: invert(1)`。**不要用 `&dark` 选择器**：`EditorView.theme` 不支持该前缀（实测抛 `RangeError: Unsupported selector: &dark`，SvelteKit 会整页渲染成 500 错误页）。
- **展开规则**：`selectionTouchesRange`（光标落在区间内含两端即展开，非空选区相交即展开）。标记类构造的展开范围必须是**标记 + 正文的并集**——标题/列表只有前导标记，只取标记范围会导致光标落在正文里时 `= ` 不露出。
- **标题字号梯度必须跟 typst 一致：1.4 / 1.2 / 1.0em、行高 1.65（用户：「在标题所在块，标题就会变的很大」）**。typst 的 heading 是 level 1 = 1.4em、level 2 = 1.2em、level 3 及以下 = 1.0em（**只加粗，不再变大**），并用和正文同一个 leading（0.65em ⇒ 1.65）。以前仿 Typora 写的是 1.8/1.5/1.25/1.08em + 行高 1.45~1.55，块级渲染落地后就变成 bug：光标一进标题块，标题比切片大 36%~40%。**标题行的上下 padding 一律不加**（周围的空白已经在相邻块的切片带里，源码形态再补一份就翻倍）。验收：`writing-mode-scenes.mjs` 的「标题字号梯度对齐 typst」**别删**。
- **选中整个公式不展开（用户要求）**：与块级同一套规则（`math-ranges.mathRevealDecision` + `selectionCoversRange`）——选区**完整盖住**公式 → 保持渲染 + 淡色底 `.cm-math-selected`；只盖住一部分、或光标在公式里 → 照旧展开。**别把它套到跨行行间公式上**（`inlinePresentation: false`）：那种公式整行 `block: true` 替换、widget 是 `contenteditable=false` 的顶层 `div`，被完整盖住后打字**会把字符插到下一行**。所以**单行**行间公式改成"装饰只盖公式本身 + widget 落在行内 + 行级居中"（`span.cm-math-block-inline` + `Decoration.line({class: "cm-math-line"})`），**别改回整行 block 替换**。**判据是"装饰实际盖住的区间"**（`decorated = block ?? 公式区间`），不是只看公式本身：单行行间公式连行首行尾空白一起盖，否则会出现"选中的是公式、widget 只被盖住一部分"（实测字符被插到行尾）。`buildMathDecorations` 与 `collectRequestsInner` 两处的判据必须用同一个 `decorated`。
- **输入 `$` 自动配对**（用户要求「自动补全 $$」）：判定全在 `auto-pair.ts`（纯函数），落事务在 `Editor.svelte` 的 `EditorView.inputHandler`（只在"空选区 + 输入内容恰好是 `$`"时介入；任何抛错都 `return false` 退回默认输入，绝不吞按键）。
  - **独占一行 → 补 `$  $`（行间公式脚手架，光标在中间）；行内 → 补 `$$`**。
  - **右侧已有闭合 `$` → 只把光标移过去**（跳过同行空白）。**这一条的判定必须排在"公式内部不配对"之前**（用户报过「依次按 `$ 1 $` 后会得到 `$1$$`」）：`$|$` 起手、敲完 `1` 是 `$1|$`，光标正好在公式内部，若走 `insideMath` 返回 `none` 就会插出不闭合的 `$`。`insideMath` 仍管"右边是公式内容"的情形（`$a + |b$`）。
  - **不配对的五类上下文**：代码 / raw / 注释 / 字符串里；代码区的紧邻右边界；已有公式内部（右侧就是 `$` 时改走"跨过去"）；前面是反斜杠；位置越界。已知代价：`#f(1)|$x$` 也要手打闭合符（按"宁可漏配对，不可误配对"取向接受）。
  - **退格整对删**（`editor-keymap.ts` 的 Backspace 命令，`Prec.high`，不接管时返回 false）：空配对 `$|$` 与脚手架 `$  |  $` 一次删干净。**返回的是"光标两侧各删几个"而不是总长度**——脚手架那对跨在光标两侧，用"向前删 N 个"会算出负数位置。
  - 空公式（`$$`、`$  $`）不会引发报错（实测 `ok=true, diagnostics=[]`）。
- **块级 widget**：**独占整行**的行间公式整行替换为居中块级 widget；```` ``` ```` 围栏代码块整段替换为等宽代码块 widget（按 typst 语义剔除公共缩进，纯文本展示不需要编译）；与文字同行的 `$ x $` 仍走行内 widget。块级/跨行替换**只能由 StateField 提供**——ViewPlugin 提供会抛 `Block decorations may not be specified via plugins`。
- **公式编译上下文**：`math-context.ts` 把「前缀」与「文档内**单行顶层** `#let` 定义」拼成 context（多行语句、含 `[...]` 内容块的语句、`= ` 后无值的半截语句一律跳过）。同名定义保留最后一次。文档定义本身有错/与前缀重名 → 父组件退回「仅前缀」重试一次。
- **性能（三处热点，勿回退）**：① `scanNonMarkupRegions` 带**单条记忆化**（一次更新里被用三处；返回的数组 `Object.freeze`，调用方只读）；② `markup-ranges` 的"是否与公式/代码区相交"判定用**二分**（`overlapsSorted`），不是线性扫描（实测 47ms → 2.6ms）；③ 编译上下文在**扩展内部**算，不要挪回页面做 `$derived`。合计：40k 字符文档一次更新 6.4ms。
- **两套 UI（仿 Typora）**：`viewMode: "write" | "source"`（取代旧的 `livePreview` 布尔，旧存档自动迁移）。
  - **写作模式**（默认，单栏）：灰底 + 居中纸张、衬线正文（打包字体，与预览/PDF 同一套字）、**字号与行高跟随文档**（默认 11pt ≈ 14.67px、行高 1.65，见块级渲染那节）、**隐藏行号槽**与当前行高亮、状态栏显示「写作」且不显示行列。公式/标记就地排版。
    - **始终自动折行，不设开关**（用户：「文档模式的内容不应该有横向拖动，而是自动换行，Alt+Z 只对代码起效」）：传给 Editor 的是 `wrap={viewMode === "source" ? editorWrap : true}`。写作模式按 `Alt+Z` 只提示规则、不动源码模式那个开关。
    - **回车换行继承上一行的缩进**（用户要求）：Enter / Shift-Enter 换成 `newlineKeepingIndent`，规则在 `auto-indent.ts`：新行缩进 = **光标左侧那一段前导空白**。**不用 CM 默认的 `insertNewlineAndIndent`**：它的缩进来自语言服务/语法树，在 typst 文档里时灵时不灵。光标停在缩进内部只取左边那一段；纯空白行回车时**清掉那串残留空白**；多行选区只替换选区。不参与 IME 判定（CM 对合成中的按键直接 return）。**一档缩进 = 4 个空格**（`INDENT_UNIT`，用户要求；typst 官方风格是 2 空格，这是用户的选择，别再"照规范"改回去）——Tab/Shift+Tab 与语言侧自动缩进都读它，回车那条不用它（照抄上一行**实际**空白）。验收第 36 组。
    - **字体必须写在 `.cm-content` 上**：CM 基础主题给 `.cm-content` 钉了 `font-family: monospace`，只改 `.cm-editor` 不生效。
    - **标题正文没有下划线**：那条下划线来自 **`@codemirror/language` 的 `defaultHighlightStyle`**（`basicSetup` 的兜底高亮），typst 只是把 Heading 子树标成 `tags.heading` 而踩上了它。修法：`typst-highlight.ts` 再挂一份 `textDecoration: "none !important"` 压掉——两者是同一元素上的两个类（CM6 高亮是类并集），**`!important` 不是可有可无的**。
    - **暗色下必须照常挂 oneDark**：CM6 基础主题自带白底黑字；不挂主题则编辑器仍是白底，而公式 widget 已被 `invert(1)` 反成白色 ⇒ **白底白字，公式"消失"**。主题变量 `--bg-paper` 同时给 `.cm-editor/.cm-scroller/.cm-gutters`。
  - **源代码模式**（`Ctrl+E`，双栏）：等宽 14px + 行号 + oneDark（暗），右侧整页预览；此模式下 live-preview 整体关闭。
    - **键位归属：`Ctrl+/` = 注释、`Ctrl+E` = 切换模式**（用户要求）。两件事曾经**同时**挂在 `Ctrl+/` 上：CM keymap 处理 `Mod-/` 时只 `preventDefault()`、**不阻断冒泡**，而菜单的 window 级匹配（`menu-keys.ts`）**不看 `defaultPrevented`** ⇒ 按一次既注释又切模式。现在 `Ctrl+/` 只归注释，模式切换在「视图 → 源代码模式」的 `shortcut: "Ctrl+E"` 上（`Ctrl+E` 经核对完全空闲）。验收第 20 组新增 3 条锁住。
    - **注释符号不用我们自己补**：`codemirror-lang-typst` 0.6.0 两个入口都声明了 `line: "//"`，`toggleComment` 直接用行注释，不必再挂 `languageData`。`editor-keymap.test.ts` 用的是**注入的替身 languageData**，真实路径由验收第 20 组在浏览器里锁。
    - **自动换行 `Alt+Z`**（用户要求）：源码模式默认不折行，长行必须横向滚动。`Alt+Z` 切换（VS Code 同款手势，菜单「视图 → 自动换行」同一入口）。**实现走 Compartment**（`wrapCompartment.reconfigure`），重建 EditorView 会丢撤销历史与光标位置。**判定必须排除 Ctrl/Meta**（Ctrl+Z 是撤销），且放在 `if (!mod) return` **之前**（Alt+Z 没有 Ctrl/Meta）。**只作用于源码模式**；开关随存档持久化（`editorWrap`，默认关）。与菜单的 Alt 不冲突（`decideMenuKey` 对 Alt+字母只返回 `exit`）。
  - **界面缩放（`Ctrl+滚轮` / `Ctrl+Shift+=`·`Ctrl+Shift+-`）**：整个界面等比缩放（**不是**分栏宽度——用户要的是"字变大"）。范围 **50%~250%**、一格 10%，默认 100%。纯逻辑在 `zoom.ts`，页面侧 `handleZoomWheel`/`setUiZoom`/`applyUiZoom`，**走 Tauri 的 webview 缩放 `setZoom`**。
    - **为什么不用 CSS `zoom`**：webview 缩放不改 CSS 像素、由引擎等比放大，所以 CM 的行高测量与 SVG 预览的尺寸计算继续正确；CSS `zoom` 会让"设置的 px"与"量到的 px"单位错位（实测 `<html>` 上 `zoom: 1.5` 后 `scrollHeight` 从 802 变 1203、状态栏被推到视口下方、`getBoundingClientRect` 与 `window.innerWidth` 两套单位混用会打烂右键菜单/Popover 定位）。
    - **监听挂在 `window` 的捕获阶段**（`{ capture: true, passive: false }`）：鼠标在任何区域滚都能缩放，且早于编辑器自身的滚动处理。**`passive: false` 不可省**。手势必须是无 Shift 的 Ctrl+滚轮，**命中时必须 `preventDefault()`**；位移量**同时读 `deltaY` 与 `deltaX`**（按 Shift 滚轮时 Chromium 把纵向转成横向——最初写成 Ctrl+Shift+滚轮，headless 全绿但真机完全没反应）。
    - **`setZoom` 只在用户操作时调一次，之后 `observeZoomEffect` 只观察、绝不改状态**（用户：「就应该缩放只有我能改，软件别自己动了」）。0.7.4~0.7.9 那套"复核发现引擎没动就把档位拉回去"已在 0.8.0 **撤销**：它判错时会把用户要的缩放弹回原档（用户反馈的「用 Ctrl+滚轮会回退」正是我们自己干的）。现在量到的读数只用于诊断（调试日志 + 状态栏一句说明），**绝不写 `uiZoom`、绝不回头改引擎**。已知代价（用户明确接受）：引擎有上限的机器上状态会高于引擎实际档位、死区的保护没了——交给用户自己按 `Ctrl+Shift+-`。**别再退回"自己拉回档位"。**
    - **滚轮位移不足一档要攒起来**（用户反馈「到上限就不可以了」）：一次滚轮的位移可以不足一档（高倍缩放下每格位移变小），档位是 10% 一格、`clampZoom` 会把算出来的 4% 圆整抹掉 ⇒ 每个事件独立计算时这种滚轮**永远**动不了，而状态栏还谎报「到边界了」（在 100% 也这么说）。现在 `accumulateWheelSteps` 把余量跨事件攒着，不足一档时只提示「滚轮这一格不足一档（攒到 N%），再滚一下就动」——**这句话本身就是判据**（不写的话"位移太小"与"事件压根没到页面"在用户眼里一模一样）。`zoomBySteps`/`resetUiZoom` 会清掉余量。验收第 40 组用真实 40px 滚轮锁住。
    - **预览永不横滚**：预览页宽是编译期决定的。① 文档没写纸张 → 注入的 `#set page(width:)` **按栏宽重排**（页宽 pt = 栏宽 px × 11/14，夹在 180pt ~ A4 宽；栏宽变化去抖 250ms 后重编译，见「编译数据流」）；② 文档**自己**写了 `#set page(...)` → 注入被覆盖，退回「固定版心 + 等比缩放」老路，画布取 `min(缩放前栏宽, 当前栏宽, 自然尺寸)` ⇒ **两条路的画布都恒 ≤ 栏宽**。代价（用户知情选定）：固定版心的文档铺满预览栏后不再继续放大；重排后预览的换行/分页不再等于导出的 PDF。验收第 30/41 组；真机侧重排由 Rust 单测 `compile_with_page_width_*` 锁住。
    - 判定"引擎接受了多少"用 **CSS 布局宽度**（`zoomFromWidths`），**别退回 `devicePixelRatio`**（真机上可能不跟随 ZoomFactor）；dpr 只作**交叉验证**写进状态栏（两条都说 1.00 = 引擎真没动；宽度说 1.00 而 dpr 说 1.50 = 我们自己量歪了）。**复核必须 fail-open**：量不到基准/宽度非法时本次不判定、不改状态。**缩放自己引发的 `resize` 不许重校 100% 基准**（`markZoomSettling` 的沉降窗口；曾把基准压低成"新宽度"，于是引擎明明接受了也被读成"限制在 100%"）。文案要带上实测数据（布局宽度、dpr、量了几次）——真机没有 devtools，状态栏截图是唯一通道。
    - 缩放**持久化**（`uiZoom`）并在启动时重新应用；到上下限后继续滚只提示不变；非 100% 时状态栏右侧常驻「缩放 xx%」徽标；视图菜单有「放大 / 缩小 / 重置缩放」（右侧灰字「Ctrl+滚轮」只是提示，MenuBar 匹配器不会命中它）。切换模式/启动恢复/页面 `focus` 时可能要把档位再设一遍（WebView2 会丢宿主设的值）。
    - **`Ctrl+Shift+=` / `Ctrl+Shift+-` 键盘 ±1 格**与滚轮走同一条链路，差别只在于没有滚轮手势（WebView2 "手势结束时抹掉 ZoomFactor"那条路径碰不到这里），所以它是缩放失败时的备用手段。
  - **状态栏最左是「错误 / 警告」计数**（用户要求 + 参照图 **⊗ 0 ⚠ 0**）：最左一个 `.badge-group`，**错误在左、警告在右**，两者**常驻显示**（无问题时是 0，避免整条状态栏抖动）。**顺序按参照图来**（最初照字面把警告放左边，用户发图纠正——**图比话准**）。
    - **两个图标都是内联 SVG**（`viewBox="0 0 16 16"`、显示 14px、`currentColor`）：错误 = 圆环 + 叉，警告 = 圆角三角 + 感叹号。**别换回字形**（`⚠` 会被彩色 emoji 字体接管、`✕` 粗细不一）。颜色：无问题 `--fg-dim`，警告偏黄 `#e5c07b`、错误偏红 `#ff8a8a`；**有内容才 `clickable`**（否则点空徽标会弹空浮层）。
