> 规则以 `CLAUDE.md` 为准；索引见 [`README.md`](./README.md)。

## 编译数据流（核心链路）

`+page.svelte` 监听内容变化 → `scheduleCompile()` → `runCompile` 拼接编译源（`ensureTrailingNewline(prefixCode) + doc`）→ 写作模式走 `compile_blocks`、源码模式走 `compileToSvg`（invoke `compile_doc { src, documentPath }`；`documentPath` = 已保存文档绝对路径 / null = 未保存）→ Rust 侧在 `spawn_blocking` 中编译（命令层互斥锁串行化，typst 引擎进程内一次一个）→ 返回结构化 `CompileOutput { ok, pages, diagnostics, warnings }`（serde `rename_all = "camelCase"`）。

前端用 `compileSeq` 代次令牌丢弃过期结果。成功：把整页 SVG 写进预览画布（`previewPaneRef.paper().innerHTML = composePages(pages)`，预览画布在 `PreviewPane.svelte` 里、经句柄 `paper()` 交出来；页间 `page-separator`）；失败：**保留最后一次成功预览**（不隐藏不报错面板），`errorLocations` 转成编辑器红色波浪线，状态栏显示错误个数。invoke/IPC 异常也收敛为错误结果。首次编译完成触发一次 `reportStartup()`。

PDF 导出：`pdf-export.ts` 由文档标题推导文件名 → 原生"另存为" → `compileToPdf` invoke `export_pdf { src, documentPath, targetPath }`，Rust 侧编译 PDF 字节直接落盘（走 `validate_write_path`）。

**诊断为 Rust 侧结构化对象**（`{ message, severity, line, column, endLine, endColumn, path }`，1-based 行列，`end` 为独占终点）。`diagnostics-utils.ts` 负责"编译源（前缀+文档）位置 → 用户文档位置"映射（`mapCompiledPosToDoc`，前缀区错误跳过）与波浪线区间（`squiggleRanges`）。

- **`path` 的"主文档"表示只许有一种（勿回退）**：Rust 侧 `Diagnostic::path` 带 `skip_serializing_if = "Option::is_none"`（主源**不带该键**），前端判据是 `d.path != null && d.path !== "" && d.path !== mainPath`，`diagnosticToLocation` 再把 `null` 归一成 `undefined`。**踩过的坑**：Rust 曾发 `"path":null` 而判据只认 `undefined`/`""` ⇒ **桌面版编译错误一条红波浪线都不画**（错误计数与列表都正常，所以看着像"能定位"）；浏览器桩当时干脆不发该字段，于是长期没抓住。现在桩按真实形状发 `path: null`（`DIAG-ERROR-MARKER` 触发假 error），验收 `wysiwyg.mjs` 第 42 组（4 项）锁死，Rust 侧另有序列化单测。**判据退回旧写法，第 42 组立刻红（做过对照实验）。**
- **文件语义 / 项目根**：主文档源码由前端传入（未保存也可编译）；**项目根 = 文档所在目录，再按文档实际引用到的相对路径自动往上放宽**（`typst_world::resolve_project_root` + `collect_required_roots`），相对 `#import`/`#include` 从磁盘按 typst 语义解析；`document_path = None` 时预检 `#import`/`#include`，给出"需要先保存文档"的诊断。
  - **为什么要放宽**：typst 的 `..` 是按**虚拟路径**判越界的，根钉死在文档目录就等于"只能导入同目录与子目录"，`#import "../touying/z.typ": *` 会报 `would escape the project root`。
  - **放宽规则照引擎语义算，别写成"目标文件的公共祖先"**：某文件（目录 `D`）里一条相对路径按 `Normal:+1 / ..:-1` 折算出冲出 `D` 的层数 `need`，根至少要是 `D` 的第 `need` 层祖先；最终根 = 所有引用（含**被引用文件自己的引用**，递归扫描、去重）的最低要求的公共祖先。反例：`Typst/touying/head.typ` 里的 `#import "../touying/z.typ"` 按目标算会得到 `Typst/touying`、仍越界。单测 `project_root_widening_rules`。
  - 跳过 `@` 包、`/` 开头（根相对）与绝对路径；目标不存在也按**词法**放宽，报 `file not found` 而不是越界。**跨卷/跨盘仍是硬限制**（单根模型决定，CLI 也一样），由 `escape_hint` 把当前项目根写进诊断。
- **版心宽是编译期输入**：预览的纸张宽度跟着预览栏走时，`previewWidthPt` 作为参数传给 `compile_doc`（Rust 注入一行 `#set page(...)`），**栏宽一变就要重编译**（见「所见即所得」里的「界面缩放」）。注入行不会让诊断行号漂移（`to_diagnostic` 只对主源减回注入行数）。

## 原生编译后端（typst_world/）

typst crate（0.15.x）内嵌进 Rust 壳，`TypstWorld` 实现 `typst::World`。要点：

- **一次编译一个实例**：命令层 `CompileState` 互斥锁保证串行（避免并发 CPU 竞争与共享状态错乱），编译在 `spawn_blocking` 执行（不阻塞 UI）。
- **字体**：`load_fonts` 从字体目录全量加载 `.ttf/.otf`（以及 `.ttc/.otc` 的每个 face，见「字体」）注册进 `FontBook`；目录不可读时返回空集（typst 给出缺字诊断）。`resolve_fonts_dir`：优先打包产物 `resource_dir/fonts`，退回仓库 `src-tauri/fonts`（开发与 cargo test 路径）。
- **接口契约**：`compile_doc → CompileOutput { ok, pages, diagnostics, warnings }`；`compile_blocks → { ok, blocks, textPt, geometryId }`（失败也必须带 `blocks` 键）；`compile_math → MathOutput`；`export_pdf → PdfResult`。`Err` 仅用于任务本身异常终止（正常编译失败仍走 `Ok(ok:false)`）。
- **前端已无 wasm**：语法高亮走 `codemirror-lang-typst/lezer`（0.6.0）。vite 里保留的 `vite-plugin-wasm` + `vite-plugin-top-level-await` + `syncWasmInit` 目前**没有服务对象**（当年是给 wasm 版 `typst()` 扩展用的），按红线 7 先留着——真要删得在 WSL/WebKit 上验一遍启动。`optimizeDeps.exclude: ["codemirror-lang-typst"]` 与三件套同生共死。
- **Linux/WSLg dev 白屏的成因与修复（勿动）**：WebKitGTK 的模块求值在模块图含**顶层 await** 时会崩掉 SvelteKit boot（TDZ → boot 整体拒绝 → 窗口纯白，外观像"应用没渲染"），Chromium 无此问题。修复三件套（均在 `vite.config.js`，**只影响 dev**）：① `syncWasmInit` 把 wasm 胶水内联为 data:URL 并同步实例化；② `optimizeDeps.exclude` 不可删（预构建阶段不走 transform，插件改写不到）；③ 匹配按**内容形状**做（helper 是箭头函数、胶水行尾无分号）——升级 vite-plugin-wasm 后若修复失效，先核对这两个形状。
- **排查 WebKit 内部问题的利器**：`WEBKIT_INSPECTOR_SERVER` 在新版 WebKitGTK 已废；webview 侧日志可临时在 `src/app.html` 挂 `window.onerror` + `invoke("write_file", ...)` 桥接出来（要求 `.typ` 后缀），用完即删。WSLg 下 WebKit 无法用 GL 时（libEGL DRI3 报错、白屏但有窗口），用 `GDK_BACKEND=x11 GDK_GL=disable WEBKIT_DISABLE_DMABUF_RENDERER=1` 强制软件渲染。

## 字体

**两条管线**：① **typst 渲染**（预览/公式/PDF）用 Rust `FontBook`，产物 SVG 是字形轮廓；② **编辑器界面文字**用 CSS 字体栈——**写作模式**把打包字体也装进了 webview（Rust `bundled_font` → FontFace），与 typst 用同一套字；**源代码模式**仍是等宽系统栈。

- **打包字体**：`src-tauri/fonts/`（7 个文件：思源宋体 / NewCMMath×3 / LibertinusSerif×2 / DejaVuSansMono）。**不放 `static/`**。新增字体同步 `download-fonts.mjs`、Rust 单测 `fonts_all_registered`、README 清单。
- **字体集 = 打包目录 + 系统目录 + 用户额外目录**（`FontConfig.dirs`，对齐 typst CLI 的 `--font-path`）。缓存**按目录列表做 key**——增删目录必须重新加载，别退回 `OnceLock` 单值缓存。
- **字体集合（`.ttc` / `.otc`）必须逐 face 注册，扩展名不能只收 `.ttf/.otf`**（用户报「字体列表和 `typst fonts` 不一样」的根因）：Windows 上 SimSun / Microsoft YaHei / 微软正黑 / 细明体全是集合，旧代码只取 face 0 ⇒ 这些字体在应用里压根不存在，连 `DEFAULT_FONT_FAMILIES` 里写着的 "SimSun" 都命中不了。现在用 typst 自己的 `Font::iter(Bytes)` 遍历每个 face（多 face 共享同一份 `Bytes`）。Rust 单测 `font_collection_registers_every_face` 用现场合成的双 face `.ttc` 锁住。
- Windows 系统字体目录也补上**「仅为我安装」的 `%LOCALAPPDATA%\Microsoft\Windows\Fonts`**；Linux 补了 `~/.fonts`。
- **与 `typst fonts` 仍会有差异，那是正常的**：CLI 走 fontdb，会列**本地化族名**与类型 1 字体，而应用只认字体文件里的**英文族名**。**判断"应用少不少字体"要看英文族名。**
- **必须注入默认字体族（`build_library`，勿删）**：不注入时中文全交给 typst 的自动回退，而回退打分是「先比衬线标记（`Libertinus Serif` 的 panose 全 0 → 被判无衬线 → 宋体全被扣分）→ 再比家族名谁短」⇒ 实测 Windows 渲染成 `KaiTi`+`LiSu`、Linux 成 `NotoSansCJKjp`。`DEFAULT_FONT_FAMILIES` = Libertinus Serif → 打包思源宋体（**子集**，生僻字靠系统字体接住）→ 系统宋体兜底 → 雅黑收尾。注入走 `Library.styles` 基础层 ⇒ **文档里的 `#set text(font:)` 仍然优先**，且不改编译源、不动诊断行号。
- **设置 → 正文字体**：选项来自 `list_font_families`；`font-settings.buildFontFamilies` 拼「拉丁基准 + 选中项 + 其余兜底」（**拉丁基准必须留最前**）。
- **字体族名写错 = 静默回退**：typst 对不存在的族名只发 `unknown font family` 警告（族名只认**英文名**）。所以 warnings 必须显示（状态栏警告徽标 + `font-warnings.ts` 的中文提示）——**删了它，"改了字体没生效"就没人知道了**。
- **正文/公式/PDF 三处同一份配置**（三个命令都收 `fontFamilies`/`fontDirs`，共用 `build_library`）⇒ 设置里改字体三处一起变；而**文档里**的 `#set text(font:)` 只管正文。`saveSettings()` 会 `resetMathCache()` 并**立即重编译**——否则预览停在上一次结果，看起来就是"改了没生效"。

## 文件操作与路径安全（src-tauri/src/paths.rs + file_commands.rs + dir_listing.rs）

- 前端用 `isTauri()` 区分桌面/浏览器；浏览器环境只显示"请使用桌面应用版本"提示页（开发模式下该页额外给了一键入口跳到 `?browserdev=1`；生产构建不显示）。
- Rust 侧 `validate_typ_path`：必须绝对路径、`.typ` 扩展名（大小写不敏感）、拒绝 `..` 穿越；`read_file` 先 canonicalize 复检符号链接；`write_file` 拒绝写入符号链接；`write_binary`（PDF 落盘）与 `export_pdf` 走 `validate_write_path`——不限制扩展名，其余安全模型一致；`list_dir_typ` 递归列 `.typ`：深度 ≤ 8、最多 500 个、跳过隐藏条目、符号链接目录不递归，返回 canonicalize 后路径。
- 无 single-instance 插件。`.typ` 文件打开走 `PendingFiles` 队列 + `emit("open-file")`：前端**先注册监听再取队列**（`take_pending_files`），避免事件落在两者之间丢失；macOS 的 Finder "打开方式" 走 `RunEvent::Opened`。
- **写盘只有一条路**：`handleSave()` → `saveTypFile()` → Rust `write_file`，而 `handleSave()` 只挂在三处显式保存上（菜单/右键「保存」、`Ctrl+S`、关窗弹窗的「保存并关闭」）。**没有自动保存、没有定时写盘**，不按保存时磁盘上的 `.typ` 一个字节都不会动。能拿走内容的只有两条：① **「新建」`Ctrl+N`**（清空编辑器 + 置空 `filePath` + `clearState()`，现在与「打开…」「Ctrl+R」一样先 `confirmDiscard`；磁盘文件不受影响）；② **「空文档 + 已有文件 + 按保存」**——**确认窗已被用户要求删掉**（原话「删了这个窗口」），现在空文档存进已有文件是**直接写空、不再问**，`needsBlankOverwriteConfirm` 连同单测一并删除。**别再"顺手加回来"。** 另外两个前提仍在：**启动恢复有安全阀**（只有 `saved.content.trim() !== ""` 才恢复，空内容连 `filePath` 一起不恢复），以及**验收第 38 组**钉住的"编辑全程 `write_file` 调用次数为 0"。**注意 `fs::write` 是"截断再写"**，不是原子写（暂未改成"临时文件 + rename"）。
- `capabilities/default.json` 的 `windows` 覆盖 `"main"` 与 `"editor-*"`，权限含 `core:window:allow-create/close/destroy/set-title` + opener/dialog + updater + `core:webview:allow-set-webview-zoom` / `allow-create-webview-window`。**新增窗口或插件功能时需同步此文件**（`scripts/capabilities.test.mjs` 会红）。

## 安全模型

`tauri.conf.json` 的 `csp` 保持 `null`（wasm 编译管线已移除、wasm 限制解除，但 CSP 未实测启用）。纵深防御 = **SVG 产物来自进程内可信编译** + Rust 路径约束（read/write/export 统一校验绝对路径、拒绝 `..` 穿越、拒绝符号链接）。若改动 csp，必须在 `npm run tauri build` 后实机测试。

## 持久化与版本

- `persistence.ts`：300ms 防抖写 localStorage（含正文 `content`、`filePath`/`fileTitle`、`dirty`、`restoreSession`）。
- **启动恢复（会话安全网）**：主题/前缀/界面模式总是恢复；**上次的正文**按设置恢复（默认开）——editorDoc 陈旧推送、误触重读、WebView 重载这类"内容没了"都能被它兜住。恢复时 `filePath`/`fileTitle`/`dirty` 一并还原；恢复出来的未保存内容会让打开新文件 / 关闭窗口照常追问。**`saved.content.trim() !== ""` 是安全阀。** 关掉开关即回到「每次全新开始」。**新建（Ctrl+N）会 `clearState()`**，有未保存内容时先确认。
- 版本号约定（0.4.0 起）：`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 的 `version` **三处一致**。CI Rust 缓存 key 基于 Cargo.lock 哈希——改动依赖会使缓存失效全量重编。**实测 rust-cache 的 key 不受根 crate version 影响**，所以只改版本号发版时缓存必然命中；Cargo.lock 内 version 必须保持合法三段式 semver（写 `"1"` 会致 cargo 解析失败）。
- 关于弹窗版本号运行时读取：`getVersion()` 返回 tauri.conf.json 的 version，发版改版本号后前端无需改动。
