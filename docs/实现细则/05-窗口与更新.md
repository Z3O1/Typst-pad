## 多窗口与页面级按键路由（Esc / Ctrl+Shift+N）

- **按键路由是纯函数**：页面级快捷键的判定全在 `app-keys.ts` 的 `decideAppKey(e, { hasFilePath, openModal })`（+ `topModal` 定 Esc 的收件人）。**顺序敏感**：
  1. **Esc** → 关最上层弹窗（关闭确认 → 更新弹窗 → 设置 → 关于；`MODAL_PRIORITY`）。
  2. **Alt+Z** → 自动换行开关（没有 Ctrl/Meta，必须排在 `mod` 门之前）。
  3. **Ctrl+Shift+N** → 新建窗口。**必须在「Shift 格式表」之前**（格式表对任何带 Shift 的组合都会 `return`，旧代码把新建窗口写在它后面 ⇒ `Ctrl+Shift+N` 从 0.7.0 起再也没触发过，直到用户报「没反应」）。
  4. **Ctrl+Shift+= / Ctrl+Shift+-** → 界面缩放 ±1 格。**必须排在「Shift 格式表」之前**（格式表是查表，`=`/`-` 不在表里、会 `return`）。
  5. **Ctrl+Shift+<键>** → 格式命令（`` ` ``/M/]/[/Q/C）。
  6. **Ctrl+R**（有文件才拦）/ **Ctrl+W**（关窗）。
  - **Esc 的语义取"破坏性最小"的那个关闭**：未保存确认 = 取消；**更新弹窗 = 只收起来（绝不写 `updateDismissedAt`**——那等于替用户点了「稍后」）；设置 = 放弃草稿；关于 = 关掉。
  - 菜单项的全局快捷键（Ctrl+N/O/S/,/P）仍由 MenuBar 处理（它 `preventDefault` 后我们的路由认 `ignored`，不会双重触发）。
- **新建窗口（`Ctrl+Shift+N`）**：`new WebviewWindow('editor-<时间戳>', { url: "/", … })`。创建失败报到状态栏（发布版没有 devtools，静默失败等于"点了没反应"）。
  - **ACL 是两个坑，都要有**：① 窗口 label 要落在 capability 的 `windows` 名单里（`["main", "editor-*"]`）——不在名单里的窗口连**应用自己的命令**都会被拒；② `new WebviewWindow()` 走 `plugin:webview|create_webview_window`，必须在 `capabilities/default.json` 里**显式**写 `core:webview:allow-create-webview-window`（`core:webview:default` **没有**这一条）。缺了它不编译报错、浏览器验收也发现不了，只在**真机点下去时**报 ACL 拒绝（0.7.9 就是这样发出去的）。`scripts/capabilities.test.mjs` 兜底。
- **副窗口 = 空白草稿窗口**（`isSecondaryWindow = getCurrentWindow().label !== "main"`）。会话（未保存内容 / 当前文件 / 脏标记）**只属于主窗口**：
  - 副窗口起来**不恢复**上次内容，并在状态栏说明「新窗口：这里的修改不会记进「上次内容」」；
  - 写存档走 `saveState(…, { session: false })`——先读回存档、把会话字段原样带过去再写（**否则副窗口改一次主题就把主窗口的未保存内容换成它那份空文档**）；
  - 副窗口点「新建」**不清存档**（`clearState()` 只由主窗口调用）；
  - **启动自动检查更新只由主窗口做**（否则两个窗口各弹一个更新窗）；手动检查不受限。
  - 残留小问题：`tauri-plugin-window-state` 按 label 记几何，副窗口 label 每次都是新的 ⇒ 状态文件会一笔一笔累积（几百字节/个，无功能影响）。
- **关联双击/跨实例打开（`open-file` 广播）在多窗口下要挑一个窗口接**：Rust 侧 `app.emit` 所有窗口都会收到，都接会同时切到同一文件。规则：**有焦点的窗口接**（顺手清空待打开队列作为"已接走"的记号），一个窗口都没焦点时**主窗口延迟 250ms 兜底**（兜底时队列已空就放手）；启动时队列里的文件**只由主窗口取**。规则实现在 `core/open-file-claim.ts`（依赖全注入，单测覆盖"谁接/谁兜底/兜底前要不要放手"），页面只注入 Tauri 侧的"有没有焦点"、待打开队列与文档会话的打开动作。
- **拖放与关闭确认的规则在 `core/window-events.ts`**（都有单测）：拖放**只认 `.typ`**（`pickTypPath` 取第一个），一个都没选中且**确实拿到了路径**时才提示「仅支持打开 .typ 文件」；关闭确认**按内容判定**（`isEffectiveDirty`）—— 输入过又删光的空文档不拦、直接关。
- **验收覆盖到哪**：浏览器里没有真的多窗口，第 35 组（11 项）锁的是**接线**（桩把 `create_webview_window` 的入参记在 `window.__browserDevWindowRequests`）。窗口本身、窗口间的存档隔离与 `open-file` 交接**只能在桌面版验证**。

## 自动更新（tauri-plugin-updater）数据流

形态 = 「静默检查 + 用户确认」（不自动下载、不偷偷重启）：**每次启动**延迟约 4 秒检查一次，发现新版本就状态栏提示 + 弹窗询问，点「下载并安装」才下载；菜单「帮助 → 检查更新…」随时可手动检查，设置里可关掉自动检查。

- **配置在 `tauri.conf.json` 的 `plugins.updater`**：`endpoints`（默认 `https://github.com/Z3O1/Typst-pad/releases/latest/download/latest.json`）+ `pubkey`（**编译进应用**）+ `windows.installMode: passive`。前端权限 `updater:default` 在 `capabilities/default.json`。
- **清单（latest.json）**：`{ version, notes, pub_date, platforms: { "windows-x86_64": { url, signature } } }`，由 `scripts/generate-latest-json.mjs` 生成（从 `bundle/nsis/*-setup.exe.sig` 读签名、按 tag 拼下载 URL、`notes` 取 `CHANGELOG.md` 该版本正文）。**优先 NSIS 而不是 MSI**（Windows 上 updater 默认走 NSIS）。
- **客户端取的是 `releases/latest/download/latest.json`** = 最新一个**已发布** Release 的资产 ⇒ **草稿 Release 不算**，必须 Publish 之后客户端才看得到（这是"发版要记得 Publish"的又一重后果）。平台键由插件自己算（本仓库只发 `windows-x86_64`）。
- **签名校验**：安装包由 CI 用私钥签、客户端用 `pubkey` 校验（Rust 侧 minisign），签名不符直接拒绝安装——这是"更新通道被换包"的唯一防线。`pub_date` 客户端按 **RFC3339** 解析。
- **前端状态机（`updateFlow`）**：`idle | checking | latest | available | downloading | installing | error` 七态**放在一个对象里**，状态栏提示、弹窗内容、按钮都由它派生——不要拆成多个布尔量。`updateHandle` 是**普通变量**（模板不渲染它），换版本前 `closeUpdate()` 释放。
- **失败反馈分两种**：手动检查失败 → 状态栏写明原因（`describeUpdateError` 翻成人话）；**自动检查失败保持安静**（只写 dbg 日志），否则网络一断每次启动都刷红字。
- **每次启动都自动检查**（mount 里按 `autoCheckUpdates` 开关挂一个 4 秒延时任务，**没有别的门**）：曾有一道"距上次检查满 6 小时才查"的节流，用户报「打开的时候没有自动更新，但是检查的时候能检查到」就是它造成的，而且手动检查还会刷新时间戳、越手动查越不会自动查。**任何"上次检查时间"式的无条件节流都不许再加回启动路径**；`lastUpdateCheckAt` 现在只是诊断记录。
- **点过「稍后」= 自动检查只更新状态栏、不再弹窗，直到用户手动检查**（用户原话「算了，不更新就再也别跳出来，直到点了检查更新」；**别再退回按时间窗口静默的版本**）。实现是持久化 `updateDismissedAt`（非 null = 别烦我）：自动检查照旧发出去（状态栏入口仍出现），但 `available` 分支不弹窗、不改状态文字（`isUpdatePromptSuppressed`）；手动检查永远弹窗。**清标记的三种显式操作**：菜单「帮助 → 检查更新…」、点状态栏入口、点「下载并安装」。缺失/坏值一律当"没点过"（免得脏值把更新通道永久堵死）。回归网是验收第 34 组（13 项）。
- **Windows 上 `downloadAndInstall` 成功后会退出应用**（NSIS 装完自己把应用拉起来），所以那个 promise 可能不返回——`{ ok: true }` 只代表"走到安装那步之前没报错"。
- **更新说明（notes）的渲染**：弹窗里由 `update-notes.ts` 渲染成**受控子集**的安全 HTML（先整体转义再生成标签）——**别再退回 `<pre>` 显示原文**（用户反馈过「更新说明无法渲染」，就是看到 `### Fixed`、`**粗体**` 原文）。故意不支持斜体/链接/原始 HTML；长度上限 8KB。
- **浏览器开发模式**：桩对 `plugin:updater|check` 返回 `null`（= 没有新版本），所以这条链路在浏览器验收里安静走通；`?browserdev=1&fakeupdate=1` 时桩返回**假的可用更新**，让「发现新版本」弹窗（含更新说明渲染）也能被验收覆盖（第 26 组）。**真实的下载/签名校验/装包只能在桌面版验证。**

## 启动耗时观测

`startup-timing.ts`：启动关键阶段打点（O(1) 无阻塞），首次编译完成后向控制台输出 `[startup]` 报告（各阶段耗时 + navigation timing 页面加载段）；Rust 侧（**仅 debug 构建**）另有 `[startup] rust phase:*` 打点（窗口创建 → webview 就绪 → 前端加载完成）。两侧同前缀，便于统一抓取对比启动性能回归。
