# 前端编辑器结构与交互

前端是 SvelteKit 单页应用。编辑器主体使用 CodeMirror 6；页面负责应用状态、编译请求、持久化与视图模式，`src/lib/editor/` 放编辑器扩展和呈现，`src/lib/core/` 放可独立验证的状态机、命令和数据处理。不要把整页应用状态再复制成长期独立的编辑器真相。

## 编辑器与模式

`Editor.svelte` 封装 CodeMirror 创建、配置、外部文档同步、事件回调和销毁。`doc` 与传入编辑器的 `editorDoc` 必须随编辑同步更新；外部文档切换、重读时要明确替换内容并清理旧会话。编辑器销毁需要取消自身创建的调度器、计时器和动画帧回调。

应用提供写作模式和源码模式。写作模式以单栏纸张和真实正文为主，直接呈现安全的 markup，公式/标记按范围装饰，复杂块按切片呈现；源码模式显示 Typst 源码及整页预览。模式间切换保留文档、撤销栈、焦点和视口内光标位置，不应通过重建编辑器来改变模式。写作模式总是折行；源码模式折行设置独立持久化。

键盘处理有明确归属：菜单项快捷键由菜单匹配器管理，带 Shift 的应用快捷键由页面按键路由管理，编辑器输入语义由 CodeMirror keymap/input handler 管理。修改按键时检查优先级与事件冒泡，避免一次按键执行两个命令。格式命令是菜单与快捷键共用的纯计划函数：无选区的块级命令包装当前整行且保留原文，有选区则只替换选区；强调/行内包装把首尾空白留在定界符之外。Typst 引用块使用 `#quote(block: true)[...]`，不要插入 Markdown `>`。

页面级按键路由在 `app-keys.ts`。顺序是行为契约：Esc 只交给当前优先级最高的弹窗；`Alt+Z` 在 Ctrl/Cmd 门之前；新窗口与缩放组合在带 Shift 的格式命令表之前；源码重读只在已有文件时拦截；`Ctrl/Cmd+W` 关闭当前窗口。菜单键盘处理仍由 MenuBar 所有，避免窗口处理器重复触发。模式键为 `Ctrl/Cmd+E`，注释为 `Ctrl/Cmd+/`。不要把 Shift 组合塞进只支持 Ctrl+单键的菜单匹配器。

写作模式 Enter / Shift+Enter 先委托 Typst 列表语言扩展的续项/退出或续行命令；未接管时，普通 markup 中 Enter 写两个源码换行作为新段落，Shift+Enter 写 Typst 显式换行（反斜线 + 一个换行）。代码、raw、注释、代码字符串和公式内仍写单个普通换行；源码模式不套用写作段落语义。普通 markup 中的直引号仍属于可编辑正文。空白行清理残余缩进，不插入孤立反斜线。两种模式的新行都沿用光标左侧实际缩进；行尾已有换行时要复用，避免多插空行。Tab/Shift+Tab 的缩进单位为四个空格。格式命令复用 `write-commands.ts` 的纯 EditPlan：取消带缩进的行首列表/标题标记时只删标记、保留缩进；行间公式选择锚点要由实际插入前缀长度计算，不能写死字符偏移。格式操作通过菜单/快捷键提供，不增加工具条。

## 段落间距

`core/paragraph-breaks.ts` 扫描纯 markup 段落之间的空白源码行，`editor/live-preview` 以行装饰压低这些行盒，保留真实空行和可编辑位置。连续空行共享一份默认段距；文末刚开新段但尚无文字时预留同一高度，避免首字输入或撤字时光标跳动。行高值以当前源码常量及真实 Typst 夹具为准，它是编辑器空白行的视觉高度，不等于 Typst `par.spacing`。

标题与列表两侧的空白行**参与**压缩：它们在编辑器里只由空白源码行代表间距，不压缩就整行多占（真实作业实测标题→列表首项偏差 +34.8px ≈ 一整行 24.2px）。**整行以 `#` 开头的代码行（`#let`/`#set`/`#show`/`#import`，以及 `#table(`/`#figure(` 这类多行调用的每一行，含收尾的 `)`）与整行注释两侧同样参与**——它们没有裁剪带承载段距（PKU 高代周二实测：这类空行全文约 16 行 × 24px ≈ 390px，与最大累计偏差同量级）；**单独成段的行间公式段落也参与**，因为它在编辑器里是可编辑段落加 `MathBlockWidget`，同样没有块带（高代周二实测最大累计偏差 429→201px）。只有真的被整段切片盖住的代码 / raw / 公式两侧不参与（裁剪带已经承载几何，压缩会重复分配段距）。注释块**内部**的空行不动。

正文或编译前缀出现活动的 `#set par(spacing: …)` 或 `#show par` 时放弃近似、保持原始留白；**只改 `leading` / `justify` / `first-line-indent` 不禁用压缩**——Typst 的段距仍是默认 1.2em，行距变化不影响段间空白。注释、raw 与字符串中的示例不算活动规则。外部导入的段落样式无法由前端扫描识别，这是当前限制。修改扫描时核对 Typst 真正的段距和连续空行、行尾选区、文末新段的浏览器验收（PKU 真实作业套件见[测试](testing.md)）。

## 布局、滚动与缩放

编辑器内容区与滚动容器职责不同：写作模式两侧阅读留白放在 `.cm-scroller`，避免整行选择背景把留白也染色。字体需落在 `.cm-content`，因为 CodeMirror 基础样式在该元素设置字体。模式切换、块点击和垂直移动应通过 CodeMirror 滚动 API 表达目标，不直接写 `scrollTop`。

CodeMirror 高度取决于是否显示滚动条；预览容器若按可用宽度反复改画布宽度，滚动条显隐会形成宽度反馈环。相关容器使用稳定滚动条槽位，尺寸观察后的重排推迟到下一帧或适当去抖。不要在 ResizeObserver 回调中同步反复读写布局。

UI 缩放使用 Tauri WebView 的 zoom 能力；CSS `zoom` 会混淆布局 CSS 像素和测量结果。缩放只能由用户命令改变，环境观察只用于报告实际比例，不能自动把用户档位改回去。布局宽度是缩放生效判定的主依据，devicePixelRatio 仅作诊断。滚轮步长不足时应累积，而不是每个事件独立取整丢掉。

缩放控制器在改档与复核期间设置沉降窗口；由缩放本身引起的 `resize` 不得重新校准 100% 布局宽度基准，否则会把有效缩放误读为未生效。读数非法时 fail-open，不据坏读数修改状态。确认/复核只观察，不回写用户档位，也不再次调用引擎；新一轮观察应作废旧代次。缩放轮次完成后才恢复正常窗口尺寸重校准。

错误与警告浮层共用一套 `openBadgePopover` 状态，关闭、Esc、点击外部、选择条目跳转和内容消失时行为一致；错误清空或警告关闭后不能留下空浮层/残余打开状态。弹出的面板固定白底黑字，颜色由页面唯一的 `--panel-*` 变量定义并由菜单、对话框、右键菜单、诊断浮层共同使用。每个面板根节点同时重绑前景、背景、边框、强调色并设置自身 `color`；悬停使用清晰的浅蓝底蓝字，面板阴影使用同一变量。状态栏诊断计数错误在前、警告在后并常驻显示 0；布局不折行，状态文本单行省略。复制诊断要保持焦点/选区，不关闭浮层或跳转。

写作模式正文字体还要**对齐 CJK 前进宽度**：Chromium 对打包思源宋体量到的 CJK advance ≈ 字号 ×1.023，而 Typst 的 CJK advance 是 1em；不补偿时每行少容约 2%、临界行比引擎早折一行。`editor-font.ts` 的 `measureWriteLetterSpacing` 用 canvas 量一次，把差值作为负 `letter-spacing` 挂在 `.cm-content` 上（并开 `text-rendering: geometricPrecision`），量不出来（jsdom / 无 canvas）就返回 0 不干预。

标题保持 Typst 的 1.4/1.2/1.0em 梯度、统一 1.65 行高；默认标题高亮可能给 `tags.heading` 加下划线，项目的补充高亮须以 `textDecoration: "none !important"` 压过默认样式。暗色模式仍需挂 oneDark；公式 widget 反色但不替代编辑器底色，避免白底白字。

## 交互与安全边界

- 菜单和弹层不应抢走编辑焦点；关闭菜单时按既定策略恢复焦点。
- 打开/重读文件必须尊重未保存修改确认；保存仍走统一文件会话写入链，不自动保存。
- 写作模式与源码模式只共享文档，不共享各自专属装饰。文档扫描、公式刷新、块编译需要分别遵守对应模块的缓存和调度契约。
- 写作模式 IME 从 compositionstart 起保护；组合过程中保持编辑器状态和正文同步，但不能让异步替换组合区域的 DOM。组件卸载需取消本组件安排的所有后台工作。
- 所有用于用户文本的装饰区间必须合法且非空（对 mark 装饰），异常应在扩展边界处理并回退到源码显示。
- 多窗口的会话归属与文件安全详见[文件与安全](files-and-security.md)：副窗口是空白草稿，不恢复/覆盖主窗口会话；副窗口改偏好时保存 `session: false`；自动更新启动检查只由主窗口执行。新窗口 label `editor-*` 必须与两处 Tauri ACL 配置匹配并授予创建 webview window 能力，失败要显示状态栏错误。`open-file` 广播由焦点窗口认领；无焦点时仅主窗口延迟兜底，启动队列也只由主窗口认领。真实焦点、窗口交接和启动文件需桌面验证。

前端模式、公式和块渲染的详细约束分别见[所见即所得](wysiwyg.md)与[写作模式渲染](writing-rendering.md)。文件安全与会话写入边界见[文件与安全](files-and-security.md)，启动分阶段日志见[调试文档](debugging.md)，通用验证选择见[测试文档](testing.md)。
