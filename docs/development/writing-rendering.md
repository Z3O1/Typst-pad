# 文档模式渲染与交互

[返回文档索引](../README.md)

## 完整编译结果是文档主体

正文、公式、表格、图片、宏输出、导入内容、页边距和分页全部由 Typst 排版。`PreviewPane.svelte` 按页序直接显示 `compile_doc` 的完整 SVG。前端负责等比缩放、滚动、主题滤镜与光标，不根据编辑器宽度注入页面设置。

不同纸型的页面按共同缩放比例显示，相对宽度保持不变。100% 时最宽页铺满预览栏，窗口宽度变化会持续更新显示尺寸；用户放大可使页面超出栏宽并横向滚动。这些展示变化不触发 Typst 重新排版。页间分隔线属于展示层；深色滤镜不修改编译产物与 PDF。

前端已删除 `live-preview`、公式队列、块装饰、字体补偿、强制断点、带高盒和空行压缩，不再调用 `compile_blocks` 或 `compile_math`。

## 在原位置展开源码

点击正文定位输入；点击公式或脚本输出，在原位置展开该表达式的完整源码，包括多行内容。`document-interaction.ts` 用现有 Lezer 语法树确定完整 `$...$` 或由 `#` 开始的表达式，包含函数名起点和参数；未完成语法退回源码行。

`document-projection.ts` 只改变本轮编译输入：把选中表达式替换为 Typst raw，自动选取不会与源码冲突的反引号围栏。多行源码使用块级 raw；`#let`、`#set`、`#show` 保留原语句执行，再显示其源码，其他表达式则被 raw 替换。整篇文档重新由 Typst 编译，展开内容的字体、尺寸、换行和后续分页也由引擎决定。Esc 恢复正常编译输入，再编译整页。

同一个 `Editor.svelte` 实例始终持有原文档、选区与撤销历史。文档模式把它作为透明输入层，定位在页面光标附近以承接键盘和输入法；它不绘制正文或展开内容。源码模式正常显示编辑器与整页预览。展开范围随源码事务映射；投影中的原文位置、编译位置与诊断通过映射换算，临时围栏不进入编辑器、保存、会话或 PDF。

空白文档、无法命中的输出和首编译失败可通过 Ctrl+E 或页面聚焦时的 Enter / F2 继续编辑。菜单、弹窗和诊断浮层优先处理自己的 Esc。模式切换不重建编辑器；离开展开态会恢复原文的编译结果。

输入仍通过 CodeMirror 修改唯一源码，`doc` 和 `editorDoc` 每次同步。保存、新建、打开、重读、窗口隔离和会话恢复复用原来的文件流程，不产生隐式写盘。文档模式保留 Typst 段落换行与列表键位；这些只决定写入什么源码。

## 整页命中与光标

`compile_doc` 在导出 SVG 的同一轮排版里收集帧几何，返回 `geometryId`。`document_geometry.rs` 按编号缓存至多 16 份最近产物，多个窗口使用各自编号；编号被淘汰后返回空命中。

- `document_hit_test` 使用从 1 开始的页号与页面 pt 坐标，返回编译源码 UTF-8 字节偏移和光标位置。重叠背景、图片与文字优先定位文字。
- `document_cursor` 把编译源码偏移映射到页面光标；没有对应输出时返回 `null`。
- 收集几何时按 Typst 的嵌套坐标变换处理位移、旋转与缩放，光标携带变换后的方向。
- 前端先将编译偏移换成 UTF-16，逆映射到原文，再减掉前缀；光标定位使用反向路径。前缀输出提示在设置中编辑。
- 光标画在 SVG 之外，随页面缩放；源码不映射到输出时隐藏光标，不猜测版面位置。

当前交互只编辑主文档；导入文件和没有可用源码 span 的合成输出不能保证精确定位。点击重复宏输出时使用命中的那份几何，但后续按源码偏移调用 `document_cursor` 不携带输出实例提示，可能定位到另一份输出。交互覆盖率不影响完整结果的显示。

## 调度、过期结果与合成

两种模式共用 `document-compile-scheduler.ts`：150ms 尾随去抖，最多一个在途编译与一份待执行需求。启动、设置保存、源码展开与收起使用立即请求；普通模式切换、滚动与容器尺寸变化不请求编译。

每次请求捕获会话号、文档修订、完整源码、展开范围、前缀、路径和字体输入。成功与失败落地前都重新核对；编辑后还没启动新编译时也不能让旧产物落地。命中额外捕获交互代次，编辑、收起和模式切换作废迟到的点击。首次保存或另存为改变相对路径解析根，需要重新编译；字体配置变化也作废旧产物。

输入法从 `compositionstart` 起暂停新编译，源码镜像仍同步；`compositionend` 后先让编辑器提交最终文本，再调度更新。组件卸载取消定时器、观察器和动画帧，使在途结果失效。

编译失败保留完整的上次成功结果，禁用旧结果的源码命中；错误只由状态栏与错误徽标呈现（预览区不画占位、更新提示和错误框，也不存在切换模式的按钮——文档模式只有文档本体，光标是唯一叠加层）。切换文件立即清空产物、光标、展开范围与旧会话交互。

验证顺序见[测试](testing.md)：先检查正常与展开状态的全部页面与真实编译产物逐节点一致，再检查点击、输入、撤销和异步作废。

## 可行性与扩展评估

以下总结基于 `c957023`（Typst 0.15.1）的源码核查与真实编译实验。**边界是当前实现的限制；优化对照是隔离探针结果；演进方案尚未实现，不能当作产品能力或性能承诺。**

当前路线适合“源码驱动的可交互排版文档”：完整 Typst 排版、唯一源码、CodeMirror 事务和同轮几何值得保留。显示任意可编译内容，不等于能无歧义地直接编辑任意输出；不应从 SVG 反推可写文档结构，也不应承诺动态宏的通用双向转换。

### 编辑与投影边界

透明编辑器管理选区和键盘输入，但页面目前没有可视选区、拖选、排版行导航或光标自动滚动。每次源码变化清除页面光标，等去抖与成功编译后恢复；空行、注释和无输出源码没有天然定位几何。持续输入和真实中文 IME 的预编辑反馈不能由人工 `CompositionEvent` 验收代替。

[`document-projection.ts`](../../src/lib/core/document-projection.ts) 仅投影本轮编译输入，不保证原始程序语义不变。原文与投影的同版本编译对照确认：

| 情形 | 实验结果 | 含义 |
| --- | --- | --- |
| `#show raw: it => []` 后展开公式 | raw 源码被隐藏，投影仍编译成功 | 展开仍受用户 show 规则影响 |
| 展开 `#context { c.step(); [标记] }`，其中 `c = counter("x")` | 后续 counter 从原文的 1 变成投影的 0 | 替换表达式也移除了副作用 |
| 展开 `$unknown_variable$` | 原文报错，raw 投影成功 | 展示有效性不等于原文有效性 |
| 240pt 页面中的 320 字符 raw 行 | 几何最右延伸到约 1,719pt | 引擎排版不保证展开源码自动折行或完整可读 |

当前 [`runCompile`](../../src/routes/+page.svelte) 只接收投影诊断；保存保留原文，PDF 重新编译原文，因此展开预览成功不能证明文件可正确导出。后续宜分离“展示产物”和“原文验证”：两者按同一会话、源码及上下文修订作废；原文验证不导出 SVG 或收集几何，原文报错也不应无条件禁用可编辑的有效投影。不可见或越界展开需要可操作的源码模式回退。

### 几何与输出身份

[`collect.rs`](../../src-tauri/src/block_geometry/collect.rs) 与 [`document_geometry.rs`](../../src-tauri/src/document_geometry.rs) 的真实帧探针确认了以下边界：

- 同一内容被宏输出两次：点击第二份后，按源码偏移重新定位可回到第一份。源码范围不是输出实例身份。
- `office` 的 `ffi` 连字对应一个 glyph，内部两个源码位置显示在同一端点；组合字符也可能对应多个源字节。合法光标停靠点不能按字节、码点或 glyph 数简单推算。
- RTL 字形的源码范围与视觉顺序相反，但当前源起点仍被画在字形左边；需要方向与光标 affinity 模型。
- `#upper("ß")` 输出的两个 `S` 的 span 对应函数名里的 `u`、`p`，不是字符串中的 `ß`。span 是来源提示，不保证对应输出字面内容；展开整个表达式是合理回退。
- 裁剪框外的文字仍被收集并可命中；几何需要裁剪与可见区域，而非只有轴对齐包围盒。
- 当前产物之后生成 16 个新快照，当前几何可被淘汰。编号防止误用其他产物，但全局 FIFO 不保证窗口的当前产物一直可交互。

扩展模型至少需要文件身份、原文/投影坐标域、输出实例、合法光标停靠点、基线与变换、裁剪、阅读顺序和来源分类。输出实例只在当前产物内有效，不能假定 Frame 路径在重排后稳定；跨产物重匹配需要源锚点和页/位置提示，歧义时回退。

### 性能实验快照

原生探针直接引用产品模块并链接现有 Cargo **debug** 依赖，分段测量 World 构建、Typst 编译、几何收集和全页 SVG 导出，绕过 Tauri。样本每页包含重复中文、English、公式和静态表格；各规模做首次生成及三次小范围修改，下表取后三次中位数，单位 ms。

| 实际页数 | World | Typst 编译 | 几何收集 | SVG 导出 | SVG 大小 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 2.1 | 8.8 | 6.0 | 11.6 | 0.10 MB |
| 10 | 3.2 | 13.6 | 72.6 | 119.6 | 1.01 MB |
| 50 | 8.9 | 27.8 | 643.4 | 580.6 | 5.09 MB |
| 100 | 15.6 | 40.2 | 1,962.4 | 1,157.7 | 10.18 MB |

MB 为十进制单位。样本没有复杂包模板、大范围重排或持续输入压力，结果不是 Windows 发布版 WebView2 指标，也不包含真实 IPC、IME 或 p95。调研探针是本地临时产物，未纳入仓库；上述数字作为测量快照保留，实施优化前应补可复现基准和目标平台验证。

热点说明与隔离对照：

- 每轮新建 World 不等于完全从零编译：字体有进程缓存，Typst eval 等环节也使用 comemo。本样本应优先优化几何与输出，不应把全部延迟归因于排版。
- 每个 glyph 都查询 `world.range(span)`。仅缓存**同轮** span 到源区间，将 100 页几何收集从约 1,962ms 降到 669ms；八组几何记录与原版完全一致。生产缓存必须绑定编译快照，不跨 Source 版本复用。
- [`composePages`](../../src/lib/core/typst-engine.ts) 直接内联全部 SVG；100 页样本有 6,871 次 ID 定义、仅 76 个不同 ID。Linux headless Chromium 中，只替换第一页仍需约 394ms 的解析与强制布局；每页 ID 命名空间隔离后约 4.6ms，独立 Shadow DOM 后约 5.3ms。三种方式首屏 PNG 相同，仅证明该首屏的有限等价，不证明跨页链接和所有模板正确。
- 因此页级更新应先建立页面宿主与 SVG 引用隔离。Shadow DOM 保留 SVG 原文，但事件、样式、页查询和链接需要适配；ID 改写会影响逐节点原样验收。完整页面验证不能因优化被移除。
- 页级导出宜在 SVG 导出前比较页面内容指纹，而不是先导出全部 SVG 再算哈希。虚拟化减少 DOM，不自动减少后端输出；应保留页面尺寸占位、共同缩放和全页几何。
- 当前几何按份数而非内存限额淘汰，comemo 缓存也需要长期编辑测量与治理；本次没有证明生产应用内存泄漏。当前产物可考虑窗口租约，历史产物另设内存预算。

### 演进顺序与待验证项

| 阶段 | 建议方向（未实现） | 验收重点 |
| --- | --- | --- |
| 正确性 | 原文诊断与投影分离、展开回退、裁剪、RTL、重复输出实例、当前几何租约 | 真实编译反例；原文保存、撤销和导出不变；晚到结果不得落地 |
| 有证据的性能优化 | 同轮 span 缓存、页面宿主隔离、页级指纹与增量输出 | 几何与完整产物一致；单页更新不触发跨页引用失效；记录分段成本 |
| 视觉编辑 | 可见选区、排版行导航、拖选、滚动跟随和真实 IME | 中文、emoji、连字、RTL、跨页、缩放、展开与编译失败状态 |
| 容量与扩展 | 虚拟化、持久 Source、依赖失效、全局编译队列公平性、多文件 | 发布版 WebView2；复杂模板；持续编辑 p95、峰值内存、多窗口与导出竞争 |

格式命令、大纲、查找及静态表格/图片参数操作可继续基于源码事务扩展。持久 Source、依赖监听或后台验证不能引入隐式写盘；全局队列可合并过期展示需求，但不能丢弃用户明确请求的导出。若仍只绘制已编译正文，输入反馈就有去抖、编译、输出和 DOM 的延迟下限；是否允许局部临时编辑层属于产品契约选择，不能伪称为行为不变的内部优化。

Tinymist / typst.ts 的当前版本、接口及实际复用成本尚未完成外部比较，不能据此排除或推荐迁移。后续应核实语义诊断、源/输出跳转、持久编译状态和增量渲染，而不把语言服务直接等同于通用视觉编辑器。验证层级与桌面要求仍以[测试](testing.md)为准。
