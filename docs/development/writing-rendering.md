# 写作模式的正文与复杂块渲染

写作模式以真实 Typst 排版为视觉基准，同时让普通正文保持 CodeMirror 的真实、可编辑文本。**单源码行**的纯 markup 段落与标题直接在编辑器中呈现；包含代码、raw 或注释，或**段内有单 LF**（Typst 把段内换行当空白、整段连排，逐源码行呈现必然多出行盒）的块，使用 Typst 输出的局部 SVG 切片，进入该块时显示源码。源码始终是唯一数据源。

公式、标记解析与内联呈现见[所见即所得实现](wysiwyg.md)；决定此呈现模型的理由与已知限制见[渲染模型](../design/rendering-model.md)。

## 编译与切片

写作模式用 Rust `compile_blocks` 对整份文档进行一次 Typst 排版，再返回顶层源块几何及按需裁出的 SVG；源码模式的整页预览使用 `compile_doc`。因此“整篇编译”是为了得到一致的排版上下文，“窗口化”限制的是 SVG 产物，不是 Typst 的语义编译范围。

切片只覆盖可见窗口附近的复杂块。窗口外只在同一会话、编译上下文与版心输入未变时才可沿用旧切片；此时按块类型和源码文本匹配旧 SVG（文档修订允许变化）。沿用块必须标为 `stale`。旧切片可暂时维持外观，不能用于精确点击命中，进入可见窗口后必须重渲。未跳过且找到的块只有在 `svg === ""` 或 `stale` 时才是待补渲；判据必须直接看块表，不能从已构造 covers 的 `revealed` 状态反推。超出 `MAX_CROP_SOURCE_BYTES`（当前 8,000 UTF-8 字节）的单块只返回几何、不生成 SVG；`skipped` 表示有意跳过，补渲判据必须先排除它。补渲去重键包含戳与窗口，同戳同窗口防止重复编译，新戳则必须允许重试。

`RenderStamp` 绑定会话、文档、编译上下文和版心布局修订；各修订号须在读取当前戳时同步更新。异步结果只有戳仍匹配当前状态才可提交。点击命中结果有三种语义：整数是精确源位置，`null` 表示无法精确定位、允许退回块首，`"cancelled"` 表示会话/文档/几何/动作已过期、必须取消整个点击。点击请求另带文档身份、geometryId 和动作令牌；其间发生新点击、键盘编辑、文档切换或鼠标接管时，旧令牌作废。即使按在普通源码上，也要推进点击令牌，避免旧的异步命中把光标拉回切片。源码编辑时旧块坐标通过 `remapBlocksThroughEdit` 映射：未改块平移或保留，被触碰的块回到源码形态；打开、新建、重读文档必须重置旧块表。过期区间必须被安全过滤，不能让装饰越界或覆盖新文本。

Rust 的 `source_blocks` 按 Typst 顶层语法产生，空行及 `#set`、`#show` 等无输出构造可能不在块表中。前端 `planBlockCovers` 再按行生成源码/切片格子，只有 covers 负责连续覆盖全文。不要把块表有洞误判成覆盖不完整。

块表里的每块除带几何外还带 **`anchorBaselinePt`（首行主基线相对带顶的偏移）**：写作模式要让可编辑块按"带高"占位时，光占高度不够，首行基线的带内偏移也要对上；浏览器侧的同一量法是"行盒顶 + 半 leading + 字体 ascent"（见[测试](testing.md)的 PKU 套件）。这两个字段就是**块级带高盒**的输入（见下）。

## 可编辑正文按"带高盒"排（`cm-block-band`）

引擎给每个块一条**首尾相接**的带（带顶/带高含前后各半个间距），所以"每块占满自己的带"就是整篇纵向对齐的充分条件。切片天然满足（SVG 的固有比例就是带高），可编辑正文则由 `block-decorations` 的 `buildBlockBandFitDecorations` 直接摆：

- `height = heightPt × 4/3`：块的盒顶/盒底与带顶/带底重合，**块间距不再靠空行反算**；
- `line-height = 2 × (anchorBaselinePt − yPt) × 4/3 − ascent + descent`：由行盒模型
  `基线 = 盒顶 + (行高 − (上升部 + 下降部)) / 2 + 上升部` 反解，让首行主基线正好落在引擎给的位置。
  上升部/下降部由 `editor-font.measureWriteFontMetrics` 用**画汉字的那一族**（思源宋体）量（`fontBoundingBoxAscent` 优先），量不出来（jsdom / 老后端 / 源码模式）整条规则不启用。

两条配套约束，缺一条就会重复计高或整片失效：

- **段落之间的空白源码行高度归零**（`markup-decorations` 的 `bandBoxes`）：段距已经含在相邻块的带里，再给空行一份就是每行多推 3px（历史上"把正文撑到带高"失败三次都是因为这个原因）。带高盒只在这一轮**每一个可编辑正文块都有几何**时启用，半套规则（一部分撑到带高、一部分按自然行盒）比不启用更差；两者同生共死 —— 空行归零也只在带高盒生效时执行（源码模式、块表过期、没有真实几何的假块都走旧口径）。
- **块切片的 `Decoration.replace` 要带 `inclusiveEnd: false`**：块的格子终点正好是下一块那一行的行首，而 CodeMirror 见到"上一块是覆盖到这个位置的块 widget"就会丢掉这一行的 line decoration（docview 的 `blockPosCovered()` / `addLineStartIfNotCovered`）。实测 87 条带高盒装饰只有 16 条落到 DOM，缺的 71 条全是"紧跟切片/隐藏块后面"的行；置 false 只改边界归属，替换区间与外观都不变。验收里有一条硬判据盯着它（"可编辑正文全部走带高盒"）。
- 标题 span 自带 1.4em/1.2em 字号，它自己的 `line-height: 1.65` 会把行盒上升部顶得比 strut 还高（基线被压低 5~7px），所以带高盒里的标题 span 一律 `line-height: inherit`。

`#let` / `#set` / `#show` / `#import` 这类**无输出语句不做几何匹配**（`SourceBlock::no_output`，`compile_blocks` 直接给 `found: false`）。原因：这些语句里的内容值（如 `#let va = $v$` 的公式）在使用处的字形其 `Span` 仍指回定义处，按源区间匹配会把全文用到该宏的字形都算进定义块，得到跨页假包围盒；前端会把这块当成一张大切片画出来，正文重复出现。`found: false` 的块按前端既有约定整格隐藏、光标进入才展开源码，与 PDF 一致。

普通可编辑段落的行距还有一层空白行装饰，用于贴近 Typst 默认段距；语义、排除范围和前缀规则见[前端段落间距](frontend.md)。源码中的空白行始终保留，并可放置光标。

## 折行：按引擎给的断点排（`cm-write-engine-break`）

**段落折成几行不再由浏览器决定**。引擎按基线聚类算出每一行的源码终点（`BlockCrop::line_breaks` /
`line_count`），前端据此在断点处强制换行 —— 浏览器只负责画，折在哪由 Typst 决定。

为什么需要：Typst 用全局最优断行，还会在行尾压缩 CJK 标点、把行尾空白挂出正文列；Chromium 是
贪心断行，同样列宽下**每行少装一个字左右**。四份真实作业 210 个可编辑块里，纯贪心时有 6 块与
Typst 差一行（两个方向都有）。现在的实现是三层叠加，缺一层都不成立：

1. **引擎给准断点**：`collect::block_lines` 按基线聚类切行、逐行取源码终点，阈值 = **文档行距
   （基线直方图自相关峰，`line_spacing_pt`）× 0.75** —— 与浏览器验收数"Typst 行数"的口径完全一致。
   两步都不能省：
   - **聚类要与"上一个行边界"比，不能与"前一个字形"比**：数学密集的段落里同一行的上下标基线
     铺得很开（相邻差 5~10pt），按相邻差聚类会把整块并成一行（实测数分周二 L154 的 6 行并成 1 行）。
   - **聚类之后还要合并"主基线相距 < 半个行距"的相邻簇**：分式的分子/分母、上下标各有自己的
     基线，累计聚类会把它们当成新的一行（实测数分周二 L54/L72 本来只有 1 行被数成 2 行、
     L154 的 5 行数成 6 行、L48 的 4 行数成 5 行）。真实的行距是整份行距（15~18pt），行内偏移
     不会超过半个行距 —— 实测真实行的主基线相隔 15.5pt（不合并），假行只相隔 4pt（合并）。
     四份作业 210 个可编辑块里这条规则只改动了那 4 个块，改完后浏览器量与引擎量 **210/210 一致**。

   断点取"上一行最右源码终点"，只有它越出块尾时才退回"下一行最左源码起点"（行内公式的源区间
   会一直伸到公式尾甚至块尾）。
2. **前端插断点 + 禁折**：断点前那个字挂一层行内 mark（`cm-write-engine-break`，`::after` 吐一个
   `\A`），并给这一行加 `cm-write-engine-break-line`（`white-space: pre`）。**禁折是必须的**：
   只插断点不禁折时，浏览器会在断点**前面**先折一次，每满一行就多一行（实测高代周二从 1 块不一致
   涨到 19 块，L128 的 5 行折成 9 行）。禁折后浏览器只在给定位置断，行数与 Typst 逐行相等。
3. **行尾压缩**：给断点前那个字一份 `letter-spacing: -1em`（其 `::after` 复位为 0）。Typst 的行
   天然比 Chromium 能装的多一点点，只禁折仍会在"差几像素"时被浏览器自行断开（实测高代周二 L268
   的引擎行自然宽 499.8px vs 495px 的列、高代周一 L63 只余 1.6px）。这一份负字距等于把该行可用
   宽度放宽 1em，而**它后面已经没有别的字**，视觉上零影响（实测各行左缘完全不变）。
4. **公式内部也要有折行机会**：Typst 允许断点落在行内公式内部（数分周二 L122 的两处断点都落在
   第 12 个字符的 `=` 上）。浏览器把整条 `$…$` 当原子 widget，只有 `segments` 之间的 `<wbr>` 才是
   折行机会，所以 `split_inline_math` 的分段门槛从"当前片段 ≥ 20 字符"降到 **10** —— 刚好覆盖
   `左边=右边` 这种最短的可断公式（见[所见即所得](wysiwyg.md)）。

三条硬约束：

- **必须是 mark 而不是 widget**：`display: block; height: 0` 的行内 widget 会让 CodeMirror 把逻辑
  行拆成多个行盒，带高盒（挂在行元素上的 line decoration）只落到第一段 —— 实测四份作业 59/26/4/43
  个块当场失去带高盒、套件 71 → 49 通过（round 12 的反面教材，改动已回滚）。mark 只给已有文本节点
  套一层行内 span，行结构与块级装饰都不受影响（`engine-break.test.ts` 用真视图钉住这条）。
- **断点必须与引擎给的行数自洽**（`line_breaks.len() + 1 == line_count`），且**有一枚落不上就整块
  不折**：落不上只可能是断点落在 `$…$`/raw 这类原子区间里（Typst 在公式内部折行，而浏览器把整条
  公式当一块），这时只折剩下的几刀等于凭空多插几刀 —— 实测高代周二 L207 因此 4 行涨到 6 行、
  数分周二 L48 从 5 行变 4 行。
- **满行的行尾会溢出正文列几个像素**（Typst 的标点悬挂观感）。写作模式的 `.cm-scroller` 因此设了
  `overflow-x: hidden`：溢出落在纸张留白里，且不许它变成横向滚动条（"出滚动条 → 版心变 → 重编译"
  正是这里要避免的反馈环）。

**结果**（2026-09-25 实测，`PKU_ROOT="$HOME/PKU" npm run verify:pku-writing` **73 项全部通过**）：
四份作业 210 个可编辑块的折行数**全部与 Typst 一致**（0/87、0/39、0/17、0/67），相邻锚点与页内
累计偏差 0 处越界，可编辑正文 100% 走带高盒，切片集合与期望一致。

## 前端呈现不变量

- 块切片使用 CodeMirror `Decoration.replace({block: true})`，范围必须对齐完整行边界。块间空行归前一格；插入、删除或编译失败期间的范围映射都不能让旧切片盖住新输入。
- 块级装饰由 `StateField` 提供；CodeMirror 不允许 ViewPlugin 提供块级替换装饰。公式、标记与切片共享装饰状态，不能生成相互重叠的 replace。被复杂块覆盖的内部标记/公式不再重复装饰。
- 光标所在复杂块必须是真实源码，保证可输入。诊断所在块也必须展开。整块选中时可保留切片并叠加选择 tint，但光标所在格仍展开；部分选择展开源码。拖选期间冻结切片版式，松手后提交选择。
- 点击切片按 Typst 排版几何映射到源字符；命中缓存是进程级共享的，故 geometryId 必须与本次切片匹配。点击链接只允许 `http`、`https`、`mailto`，链接按下要阻止默认焦点转移。滚动目标与选择提交要在同一事务内完成。
- 竖直光标移动沿源码行前进，保留列并经过空行；跨页移动仿 CodeMirror 的页面移动。不要退回“一次跳过整个块”。滚动锚定使用 CodeMirror 的 `scrollIntoView`，不要直接改 `scrollTop`。
- 视口内切片随文档字号、行距和打包字体呈现；正文 SVG 与源码透镜应保持字号和行高一致。块带须夹紧到下一块顶端，避免脚注等远处墨迹把中间块挤没。Typst 语义决定块分区：行内 `$x$` 与 inline raw 不因单独占行就成为块间断点。
- 编译窗口按字符范围选块，单个极大块可能一直与窗口相交，因此需保留 8,000 UTF-8 字节的单块上限。若将来实现超大块可视带切片，必须同时表达带内偏移与整块高度；当前行为是让该块以源码编辑。

写作编译由 `writing-compile-scheduler` 单槽调度：最多一个在途任务和一份合并后的待执行请求。编辑采用尾随 150ms 去抖，滚动/重排不延长编辑等待；公式请求可让块编译再等 240ms。所有入口（编辑、窗口补渲、版心变化、设置或上下文变化、启动）登记到调度器；需要立即完成的上下文变更走 `requestNow`，不能绕开调度器。输入法从 compositionstart 到结束期间不启动新后台编译；结束后按最终文档状态排队。公式呈现刷新按绘制帧合并，扫描结果按 CodeMirror `Text` 身份缓存，纯选区移动与滚动不应重新扫描全文。卸载时取消排队工作、写作重排计时器及刷新回调。

## 几何与回退

Typst 允许字形越出布局帧。裁剪必须以墨迹包围盒为准，而不是仅用 frame 尺寸；递归几何需应用 group 仿射变换，文字取字形边界、图形取 shape 边界。块带范围需要限制在相邻源块之间，退化时保留最小有效带而不是丢弃块。源块几何、链接热区和 SVG 使用同一裁剪坐标系。

无输出块只可在成功编译确认无墨迹时隐藏；编译失败、块过期或后端缺少 `compile_blocks` 能力时必须保留可编辑源码/旧路径回退。诊断不得被切片遮盖。`blocks` 响应字段即使失败也必须存在，以区分“编译失败”和“旧后端不支持命令”。

## 当前限制

- SVG 切片没有文字层，因此切片中的浏览器查找、拼写检查和无障碍读取受限；复制仍以源码为准，未提供从 SVG 提取排版纯文字；真实正文仍保有可编辑文本。
- Typst 将脚注正文排到页底，或通过 `#place` 放置的浮动内容，可能位于对应源块裁剪带之外，当前写作呈现不会完整显示这些内容。
- 表格仍按整体复杂块处理；行数较多的表格或超长代码块在光标进入时自然增高。代码/表格源码比排版结果高时，有限占位不能消除源码本身的高度差。
- **折行位置已按引擎断点对齐**（见上节「折行」）：四份作业 210 个可编辑块的行数与 Typst **逐块相等**
  （0/87、0/39、0/17、0/67）。这不是字体度量的功劳（CJK 前进宽度已精确补偿到 1em、公式 widget 宽与
  夹具误差 ≤0.03px），而是"引擎给断点 + 浏览器禁折 + 行尾压缩 + 公式内留折行机会"四件事凑齐的结果；
  少任何一件，都会有整块退回浏览器的贪心折行（实测每一件的缺失都对应一次红）。
- **段内有单 LF 的段落以切片呈现**：Typst 把段落内的单换行当空白、整段连排（PKU 实测一块源 6 行 → 引擎 5 个视觉行），而逐源码行的可编辑文本每行必占一个行盒（同一块浏览器 9 行），纵向位置从这一段起就对不上。这类段落因此与复杂块同路（切片 + 光标进入展开源码），代价是未进入时整段不可直接编辑。编辑器自己的 Enter 写两个换行（新段落）、Shift+Enter 写 `\` + 换行（Typst 显式换行），都不产生"段内单 LF"，所以只影响粘贴/手写的硬折行文本。
- markup 直引号可作为编辑文本；引用、标签及未支持的简写等结构在直接文本呈现下可能以源码形态出现。行内 raw/link 是否加入有限白名单尚属产品决策，见[后续设计建议](../design/rendering-model.md)。
- 性能阈值与真机 IME / 多窗口行为应通过当前浏览器和桌面验收确认；历史报告里的计数、分支和机器基线不是规范。
