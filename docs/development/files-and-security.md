# 文件操作与安全边界

贡献者环境见 [`testing.md`](testing.md)，编译与导出细节见 [`compiler-backend.md`](compiler-backend.md)。

## 文件命令

Tauri 文件 IPC 实现在 `src-tauri/src/file_commands.rs`、`dir_listing.rs`、`paths.rs`。前端通过 `isTauri()` 区分桌面端；浏览器运行模式只提供开发验收入口，不具备真实文件访问能力。

`.typ` 读写路径必须是绝对路径、扩展名为 `.typ`（大小写不敏感），并拒绝 `..` 穿越。读取前 canonicalize 并复检符号链接；写入拒绝符号链接。二进制写入和 PDF 导出由 `validate_write_path` 统一校验，不限制扩展名，但仍需满足路径安全约束。目录列表只递归 `.typ` 文件，最多深入 8 层、收集 500 个，跳过隐藏项且不递归符号链接目录。

当前 `write_file` / `write_binary` 使用 `fs::write`，语义是截断目标再写入，不是临时文件加 rename 的原子替换。若写入中途失败，目标文件可能已经被截断或部分写入；不要把现状描述成原子保存，改变写盘策略需单独评估恢复与替换语义。

文件关联打开通过 `PendingFiles` 队列和 `open-file` 事件传递。前端必须先注册事件监听，再读取待处理队列，避免两步之间到达的文件丢失。不要引入不经路径校验的读写入口。

## 文档保存与会话

持久化分为浏览器本地会话状态与显式文件保存。会话状态由 `src/lib/core/persistence.ts` 防抖写入 localStorage；文档磁盘写入唯一通路是 `document-session` 的 `save()` → `saveTypFile()` → Rust `write_file`。没有自动保存或定时写盘；编辑、切换文档或关闭窗口不得绕过该通路写入文件。

恢复上次正文受设置控制，且只恢复非空内容；正文、文件路径、标题和脏状态作为会话整体恢复。副窗口不拥有主窗口的文档会话：修改偏好时需保留已有会话字段，不能用副窗口的空文档覆盖主窗口恢复内容。只有主窗口清理主会话存档。

新建、打开、重载和恢复正文建立新的编辑器会话并清空撤销历史，即使正文与前一会话相同也不例外；新会话内的编辑仍可正常撤销。替换先通过 CodeMirror 公开事务同步正文与起始选区（包括启用的 EditContext 输入上下文），再在同一视图中建立无历史的新状态。保存、另存为、模式切换与偏好设置变化保留当前会话的历史、编辑器视图和生效扩展配置。

新建、打开、重载和关闭等可能丢弃未保存内容的操作遵循文档会话确认逻辑；打开当前文件的同一路径也必须确认未保存修改。「未保存修改」的判据是正文与基线（上次打开/保存/新建时的内容）不同（`doc-utils.isDocModified`），不是“编辑过”的标志位、也不是“正文是否为空”：打开一篇有内容的文件再全选删光算改过，打字后又撤销回原样不算；存档恢复出来的未保存文档没有基线，保守按有修改处理。窗口标题的文件名后加小圆点标记同一判据（原生标题栏字号不可控，只用更小的字形）。空文档保存到现有文件时直接写入空内容，不增加额外确认步骤。保存到当前正在编辑的同一路径时，不要求“覆盖确认”；保存为另一个路径则由原生保存对话框和操作系统处理同名文件替换。

## WebView 与能力配置

Tauri 权限由 `src-tauri/capabilities/default.json` 控制。窗口标签必须与 capability 的 `windows` 模式匹配；新窗口能力还需包含 `core:webview:allow-create-webview-window`。新增窗口或插件功能时同步审查 capability，并运行 `scripts/capabilities.test.mjs` 所覆盖的权限检查。

`src-tauri/tauri.conf.json` 的 CSP 当前为 `null`。若改变 CSP，需经过生产桌面构建和实际 WebView 验证；浏览器开发模式不能代表 Tauri CSP 行为。更新器权限也由 capability 明确授予。

## 外部文件变更

当前窗口只监控**当前主文件**（`src-tauri/src/file_watcher.rs`）。外部程序修改磁盘后：

- 若编辑器**没有未保存修改**，自动重读磁盘内容并建立新会话（清撤销历史）。
- 若编辑器**有未保存修改**，弹出原生确认框让用户选择「重读磁盘」或「保留当前内容」；
  选择保留后，同一磁盘版本不会重复打扰，但新的外部版本仍会再次提示。
- 文件删除或短暂不可读时给出非破坏性状态提示，保留当前内容。

实现边界：

- 监控随 `filePath` 变化自动切换/解绑；新建、另存为、关闭都会停止旧 watch。
- 监听文件所在**父目录**并过滤文件名，能捕获原子替换（`rename` 覆盖）。
- 事件经 `notify-debouncer-mini` 去抖（150ms）；自己的 `write_file` 触发的事件若内容与实际写入快照基线一致会被忽略，即使保存等待期间继续输入也不误报。保存只更新路径、标题与写入快照基线，不修改等待期间的正文、选区或撤销历史。
- 读盘与提示串行合并最新事件；每个异步结果核对路径、会话和正文修订。路径/会话变化或卸载彻底作废旧工作；同身份输入/撤销只作废旧选择，保留已知外部版本并单槽去抖重查，即使没有第二个文件事件，直接保存仍须冲突确认。先注册事件监听，再启动观察并补读磁盘，避免启动间隙漏变更。
- 显式保存从同步入口持有路径/会话/代次绑定的令牌，期间保留事件但暂缓外部检查；确认前已有的检测需求先核对磁盘。已知外部版本冲突须确认并复检版本；确认期间切会话或磁盘变更则拒绝这次保存。实际 write 回复并应用快照基线后，或取消/失败后，`finally` 恢复最新检测需求。旧会话的令牌不能解除新会话的保存槽或清冲突。manager 的提示占用独立于保存授权：切身份立即作废旧授权，但已显示的 dialog 真正结束（同意、取消或拒绝）前仍串行占用提示槽，随后消费新身份的最新需求；只有旧 write 回复在途时，不阻塞新身份观察。保存结果不能盲清期间出现的新冲突。写盘仍走唯一 `write_file` 入口，不自动写盘。
- 原生命令以 Tauri 注入的调用窗口隔离，不接受前端提供的窗口标签；窗口销毁时 backend 清理 watcher，即使 JS 未卸载。
- 浏览器开发模式无真实文件监控。`external-file-change.test.ts` 覆盖异步状态机；`scripts/browser-check/file-changes.mjs` 用 dev-only 假事件、磁盘版本和延迟响应验证真实页面接线（31 项，无真实排版夹具依赖）。原生 `file_watcher` 测试通过命令共用的状态/发射回调验证临时文件写入、同长度变更、原子替换后继续编辑、窗口隔离和清理。两层都不替代 Windows WebView2 实机验证。
